### Exam Title
Debug & Fix: Practical Code Repair for Entry-Level Computer Programmers (Basic)

---

### Instructions for Candidate

You have 90 minutes total. Use only the provided code execution environment and a text editor. Do not use internet resources.

Follow these steps exactly:

1. Read the repository README (provided) and note the exact command to run the test runner (examples you might see: ./run_tests.py, ./run_tests.sh, or python3 -m run_tests). If the README gives a different command, use that one.

2. Start a timer. Record the start time.

3. Run the test runner immediately (before changing any files) and capture the full console output. Save this output — you will paste it into test_submission.json.

4. Reproduce and diagnose failures:
   - For each failing task, inspect the code and tests. Formulate a hypothesis for the root cause.
   - Make minimal targeted changes to fix the bug(s). Do not rewrite unrelated modules or reformat entire files.
   - After each change, re-run the test runner to verify the effect.

5. Work through the tasks in order (1 → 4). Later tasks depend on earlier fixes; run the full test runner frequently to ensure no regressions.

6. When all tasks are complete (or when you must stop), run the test runner one final time and capture the full console output exactly as produced.

7. Prepare the required submission file test_submission.json (details below) and include all modified source files in the repository root (or in their original paths). If you computed checksums include them in the JSON (optional but recommended).

8. Stop the timer and record total time spent (must be ≤ 90 minutes).

Notes:
- Make minimal changes necessary to fix each problem. The evaluator will review diffs and may deduct points for large, unrelated edits.
- If you must make a behavioral decision for an ambiguous edge case, choose a reasonable behavior, implement it, and document your decision in the JSON notes field.
- The test runner is authoritative: automated tests determine task correctness objectively. Your explanations in test_submission.json are used for reproducibility and partial credit.

Time guidance (suggested):
- Initial read + first run: 5–10 minutes
- Task 1: 15 minutes
- Task 2: 25 minutes
- Task 3: 30 minutes
- Task 4 + final run + JSON prep: 10–15 minutes

### Task Description

You will be given a single project repository containing a runnable program and an automated test runner. The repository contains four debugging tasks of increasing complexity. For each task, do the following:

Task 1 — Quick fix (approx. 15 minutes, 15 points)
- Reproduce a trivial failing case (syntax/typo or wrong constant).
- Make the minimal code change to stop the crash or produce the obviously-correct result.
- Verify the test(s) for Task 1 pass.

Task 2 — Logic bug (approx. 25 minutes, 30 points)
- Fix a logic error (off-by-one, wrong conditional, incorrect operator) that yields incorrect output for provided inputs.
- Make a focused change and verify the test(s) for Task 2 pass.

Task 3 — Data handling / edge case (approx. 30 minutes, 35 points)
- Fix a runtime failure or incorrect behavior for an edge case (empty input, unexpected format, null values).
- Make the code robust with minimal, well-justified changes. Verify Task 3 tests and related tests pass.

Task 4 — Small integration / regression check (approx. 20 minutes, 20 points)
- Fix remaining issues (formatting, integration, regression introduced by previous bugs).
- Ensure the full test suite passes and final output(s) match expected golden files.

All tasks are judged by the provided automated tests; your job is to make the program and tests pass by modifying source code in the repository.

### Submission Format

Create a file named test_submission.json at the repository root. This file must be a single JSON object with the exact fields below. All listed fields are required unless marked optional.

Top-level fields:
- candidate_name (string) — Your full name.
- task_results (array of 4 objects) — Ordered list for tasks 1→4. Each object must include:
  - task_id (integer) — 1, 2, 3, or 4
  - files_changed (array of strings) — relative paths of files you modified for this task (empty array if none)
  - change_summary (string) — up to ~200 words describing what you changed (concise)
  - root_cause (string) — short explanation of the root cause of the failure
  - how_tested (string) — commands you ran and exact test runner output lines demonstrating the result for this task (paste exact lines)
  - time_spent_minutes (integer) — whole minutes spent on this task (sum should not exceed total_time_minutes)
  - confidence_level (string) — one of: "high", "medium", "low"
  - notes (string, optional) — any assumptions or trade-offs made (if none, use empty string)
- final_test_output (string) — full console output (paste-as-is) from the final run of the provided test runner after all your changes
- total_time_minutes (integer) — total minutes elapsed for the entire exam (must be ≤ 90)
- checksum_of_modified_files (object, optional) — mapping of filename -> SHA256 hex digest for each modified file (recommended, but optional). If omitted, use an empty object {}.
- final_score_self_assessment (integer 0..100) — your self-assessed confidence that your submission is fully correct (0 = not correct, 100 = definitely correct)

Additional rules:
- test_submission.json must be valid JSON (UTF-8 encoded).
- For files_changed list, use relative paths exactly as in the repository.
- For how_tested, include the exact command(s) you typed to run tests and the exact lines from the test runner that indicate pass/fail for that task. For the final_test_output field, paste the entire final run output verbatim.
- If you make any behavioral choices for ambiguous inputs, document them in the task's notes field.
- Keep changes minimal and local to the files that need fixing.

# parser.py
# Responsible for reading CSV files into header + rows
# Intentional bug present for Task 1 (syntax/typo to fix)

def read_csv(path):
    with open(path, 'r') as f
        lines = f.readlines()
    header = lines[0].strip().split(',')
    rows = [line.strip().split(',') for line in lines[1:]]
    return header, rows

# aggregator.py
# Responsible for producing totals per product.
# Contains logic bugs for Task 2 (off-by-one) and Task 3 (no handling of empty quantities).

def compute_totals(rows):
    """
    rows: list of lists, each row as [Transaction_ID,Customer_ID,Product_Code,Quantity,Region]
    Returns: dict product_code -> total_quantity
    """
    totals = {}
    # BUG: off-by-one: starts at index 1, skipping the first data row
    for i in range(1, len(rows)):
        row = rows[i]
        product = row[2]
        quantity = int(row[3])  # BUG: will raise if empty string
        totals[product] = totals.get(product, 0) + quantity
    return totals

def find_top_product(totals):
    """Return product code with highest total (string)."""
    if not totals:
        return None
    top = max(totals, key=totals.get)
    return top

# app.py
# Simple orchestrator that ties parser -> aggregator -> formatter

def run(input_path, output_path):
    header, rows = read_csv(input_path)  # expects parser.read_csv to be available when loaded by run_tests
    totals = compute_totals(rows)        # expects aggregator.compute_totals to be available
    top = find_top_product(totals)       # expects aggregator.find_top_product to be available
    report = {"products": totals, "top_product": top}

#!/usr/bin/env python3
"""
run_tests.py

Automated test runner for Tasks 1-4.
Run: python3 run_tests.py

This script loads modules from src/ (by file path) and executes small checks.
It prints Task1..Task4 PASS/FAIL lines and exits with non-zero if any task failed.
"""

import sys
import os
import json
import traceback
import importlib.util
from pathlib import Path

ROOT = Path(__file__).parent
SRC = ROOT / 'src'
DATA = ROOT / 'data'
OUTPUT = ROOT / 'output'
EXPECTED = ROOT / 'expected_outputs'

OUTPUT.mkdir(exist_ok=True)

def load_module(name, path):
    spec = importlib.util.spec_from_file_location(name, str(path))
    mod = importlib.util.module_from_spec(spec)
    try:
        spec.loader.exec_module(mod)
        return mod, None
    except Exception as e:
        return None, traceback.format_exc()

results = {}

# Task 1: Parse header check
parser_mod, parser_err = load_module('parser', SRC / 'parser.py')
if parser_err:
    print("Task1: FAIL")
    print("  parser import error:")
    print(parser_err.splitlines()[:5])
    results[1] = False
else:
    try:
        header, rows = parser_mod.read_csv(str(DATA / 'transactions.csv'))
        expected_header = ['Transaction_ID','Customer_ID','Product_Code','Quantity','Region']
        if header == expected_header:
            print("Task1: PASS")
            results[1] = True
        else:
            print("Task1: FAIL")
            print("  header mismatch:")
            print("    got:     {}".format(header))
            print("    expected:{}".format(expected_header))
            results[1] = False
    except Exception as e:
        print("Task1: FAIL")
        print("  error during read_csv:")
        traceback.print_exc(limit=2)
        results[1] = False

# For Tasks 2-4 we require parser to be correct; if Task1 failed, mark dependent tasks as failed/skipped.
if not results.get(1, False):
    print("Task2: FAIL")
    print("  skipped because Task1 failed (parser not available)")
    print("Task3: FAIL")
    print("  skipped because Task1 failed (parser not available)")
    print("Task4: FAIL")
    print("  skipped because Task1 failed (parser not available)")
    sys.exit(2)

# Task 2: Aggregation logic check
aggregator_mod, aggregator_err = load_module('aggregator', SRC / 'aggregator.py')
if aggregator_err:
    print("Task2: FAIL")
    print("  aggregator import error:")
    print(aggregator_err.splitlines()[:5])
    results[2] = False
else:
    try:
        totals = aggregator_mod.compute_totals(rows)
        expected = {"P01": 9, "P02": 3, "P03": 6}
        if totals == expected:
            print("Task2: PASS")
            results[2] = True
        else:
            print("Task2: FAIL")
            print("  totals mismatch:")
            print("    got:     {}".format(totals))
            print("    expected:{}".format(expected))
            results[2] = False
    except Exception as e:
        print("Task2: FAIL")
        print("  error during compute_totals:")
        traceback.print_exc(limit=2)
        results[2] = False

# Task 3: Edge case handling (empty quantity field in transactions_edge.csv)
try:
    header_e, rows_e = parser_mod.read_csv(str(DATA / 'transactions_edge.csv'))
except Exception:
    print("Task3: FAIL")
    print("  parser read_csv failed on edge file")
    results[3] = False
else:
    if not results.get(2, False):
        print("Task3: FAIL")
        print("  skipped because Task2 failed (aggregation may be incorrect)")
        results[3] = False
    else:
        try:
            totals_e = aggregator_mod.compute_totals(rows_e)
            # Expect same totals as before since empty quantity should be treated as 0
            expected = {"P01": 9, "P02": 3, "P03": 6}
            if totals_e == expected:
                print("Task3: PASS")
                results[3] = True
            else:
                print("Task3: FAIL")
                print("  totals on edge file mismatch:")
                print("    got:     {}".format(totals_e))
                print("    expected:{}".format(expected))
                results[3] = False
        except Exception as e:
            print("Task3: FAIL")
            print("  error during compute_totals on edge file:")
            traceback.print_exc(limit=2)
            results[3] = False

# Task 4: Full pipeline & formatting: produce output/report.json and compare to expected_outputs/golden_report.json
formatter_mod, formatter_err = load_module('formatter', SRC / 'formatter.py')
if formatter_err:
    print("Task4: FAIL")
    print("  formatter import error:")
    print(formatter_err.splitlines()[:5])
    results[4] = False
else:
    try:
        report = {"products": totals, "top_product": aggregator_mod.find_top_product(totals)}
        outpath = OUTPUT / 'report.json'
        formatter_mod.write_report(report, str(outpath))
        with open(outpath, 'r') as f:
            produced = json.load(f)
        with open(EXPECTED / 'golden_report.json', 'r') as f:
            expected = json.load(f)
        if produced == expected:
            print("Task4: PASS")
            results[4] = True
        else:
            print("Task4: FAIL")
            print("  produced report differs from golden:")
            print("    produced: {}".format(json.dumps(produced, indent=2)))
            print("    expected: {}".format(json.dumps(expected, indent=2)))
            results[4] = False
    except Exception as e:
        print("Task4: FAIL")
        print("  error during pipeline/formatting:")
        traceback.print_exc(limit=2)
        results[4] = False

# Summary and exit code
all_pass = all(results.get(i, False) for i in (1,2,3,4))
if all_pass:
    print("\nAll tasks passed.")
    sys.exit(0)
else:
    failed = [str(i) for i in (1,2,3,4) if not results.get(i, False)]
    print("\nTasks failed: " + ", ".join(failed))
