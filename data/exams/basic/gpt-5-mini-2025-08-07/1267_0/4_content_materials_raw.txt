# calculations.py
# Provides small numeric utilities.
# Note: This file contains seeded bugs for the exam.

def sum_numbers(nums)
    # Return the sum of a list of numbers.
    # BUG: missing colon in function definition (Task A)
    return sum(nums)

def max_gap(nums):
    """Return maximum difference between consecutive sorted numbers.
    If list is empty or has one element, return 0.
    """
    if not nums or len(nums) < 2:
        return 0
    nums_sorted = sorted(nums)
    # BUG: incorrect aggregation used (returns the minimum gap instead of the maximum) (Task B)
    gaps = [nums_sorted[i+1] - nums_sorted[i] for i in range(len(nums_sorted)-1)]
    return min(gaps)

def average(nums):
    """Return the average of a list of numbers. Return 0 for empty list."""
    if not nums:
        return 0
    # This returns an integer due to int() conversion but tests expect a float in some contexts.
    return int(sum(nums) / len(nums))

# utils.py
# Helper utilities for string processing.

def normalize_names(names):
    """Normalize a list of name values:
    - strip whitespace
    - convert to lower-case
    - remove empty names
    """
    # BUG: This comprehension assumes every element is a string and calls strip()
    # If an element is None this will raise AttributeError. (Task C)
    return [n.strip().lower() for n in names if n.strip()]

# main.py
# Integration functions that use calculations and utils.

from . import calculations
from . import utils

def generate_report(data):
    """Given data with keys:
       - 'numbers': list of numbers
       - 'names': list of names (strings or empty/None)
       Return a dict with keys 'total', 'max_gap', 'names'.
    """
    numbers = data.get('numbers', [])
    names = data.get('names', [])

    total = calculations.sum_numbers(numbers)
    gap = calculations.max_gap(numbers)
    normalized = utils.normalize_names(names)
    return {
        'total': total,
        'max_gap': gap,
        'names': normalized
    }

def test_generate_report_integration():
    data = {'numbers': [1,8,0], 'names': [" Alice ", "Bob", ""]}
    report = main.generate_report(data)
    # total 1+8+0 = 9
    assert report['total'] == 9
    # sorted numbers [0,1,8] => gaps 1 and 7 => max_gap should be 7

Overview of construction
- Goal: Provide a compact, deterministic codebase with four seed defects mapped to Tasks A–D that collectively test the candidate's ability to reproduce failures, perform targeted fixes, and validate with tests.
- Language: Python (quick to run and edit).
- Repository size: 3 source modules (calculations, utils, main) + 4 unit test files and a small run script. This keeps edit scope small and allows completion within 90 minutes.

Mapping of seeded defects to tasks
- Task A (Quick run/compile failure):
  - Seeded bug: app/calculations.py has a syntax error (missing colon in function def for sum_numbers).
  - Observable symptom: pytest immediately fails during import with a SyntaxError pointing to calculations.py. This validates candidate can run tests and read the stack trace.

- Task B (Single logical bug):
  - Seeded bug: calculations.max_gap builds gaps correctly but returns min(gaps) instead of max(gaps).
  - Observable symptom: test_max_gap_two_numbers (and integration test) assert a larger gap but current function returns the smallest gap. Candidate must locate the wrong aggregation and correct it (min -> max).

- Task C (Edge-case / input validation):
  - Seeded bug: utils.normalize_names assumes all list elements are strings and calls strip(); when an element is None it raises AttributeError.
  - Observable symptom: test_normalize_names_mixed raises AttributeError during test. Candidate should add a safe check to skip non-string values or coerce safely.

- Task D (Integration/regression):
  - Purpose: Ensure changes in calculations and utils integrate correctly through main.generate_report.
  - The integration test expects numeric aggregation and normalized names. The earlier tasks' fixes must allow the integration test to pass; this probes cross-module interaction (data flow from tests -> main -> calculations/utils).

Design rationale and relationships
- Tests are small and focused; each test exercises a clear behavior and pins expectations numerically or by exact string lists so fixes are verifiable.
- Multi-step debugging chain: Task A prevents subsequent tests from running until it's fixed. After Task A, Task B's failing tests point to calculations.max_gap, but the failing test may be observed in Task D as well, requiring tracing from main -> calculations.
- Data dependencies: main.generate_report composes functions from calculations and utils. The integration test in Task D ensures the candidate reasons about returned types and content across modules.
- Decision point: For Task C (normalize_names), the candidate must choose whether to accept None values and coerce them, or to skip them. Tests assert that None and empty string are removed; therefore the expected fix is to ignore non-str or empty entries and return only normalized strings.
- Minimal invasiveness: each seeded bug is fixable with a one-line or small multi-line change. Evaluators should prefer minimal edits.

Common incorrect approaches / traps
- Editing tests to make them pass. Tests must remain unchanged.
- Overly broad changes: rewriting functions or returning different types (e.g., changing average to return int everywhere). Only minimal, targeted changes are expected.
- For Task B: simply changing initialization of gaps or sorting may pass some cases but break others; the intended change is to use max(gaps).
- For Task C: candidate might accidentally treat numeric values as strings; ensure the fix checks instance types.

Expected fixes (concise)
- app/calculations.py:
  - Add missing colon to def sum_numbers(nums):
  - Change return min(gaps) to return max(gaps)
  - (Do not change average unless necessary — tests do not exercise average besides its existence.)
- app/utils.py:
  - Update normalize_names to skip None and non-str values, and ignore empty strings after strip.
  - Example safe implementation: result = [n.strip().lower() for n in names if isinstance(n, str) and n.strip()]
