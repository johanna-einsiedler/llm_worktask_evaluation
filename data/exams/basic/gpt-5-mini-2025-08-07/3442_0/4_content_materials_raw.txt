How the materials were constructed and why

1) Construction goals
- The dataset models short system telemetry / event logs with columns required by the exam: id, timestamp, component_id, metric_value, status_code, message.
- The dataset size is 60 rows to keep the workload small but allow one day to exceed the threshold N = 50 so the candidate must produce a non-empty result for the "days with more than N events" query.
- The components_lookup.csv is provided so the required join (human-readable names) can be performed without inventing mappings.

2) Key patterns and relationships intended for grading
- Day distribution:
  - Intended assignment: 52 events have timestamps on 2025-01-10 and 8 events on 2025-01-11 (raw CSV). This ensures 2025-01-10 has more than N=50 events.
  - Two rows have malformed timestamps (id 10 and id 58). If the candidate drops malformed timestamps, counts become: 2025-01-10 => 51 events; 2025-01-11 => 7 events. Either approach (keep or drop malformed-timestamp rows) is acceptable so long as the candidate documents and uses the same choice consistently; the evaluator must accept both but verify the candidate's stated handling.
- Metric completeness:
  - Three rows have invalid metric_value entries (id 7: empty, id 18: "NaN", id 55: "abc"). Candidates must decide to drop or coerce these rows for numeric aggregations. The exam requires explicit handling and justification.
- Component distributions (to allow grouping, averages, and error-rate computations):
  - comp_A: 20 events (IDs 1–20) with high metric_value (~410–500).
  - comp_B: 15 events (IDs 21–35) with medium metric_value (~230–310).
  - comp_C: 10 events (IDs 36–45) with low metric_value (~55–90).
  - comp_D: 8 events (IDs 46–53) with mid-high metric_value (~160–210).
  - comp_E: 7 events (IDs 54–60) with very low metric_value (~12–22).
- Errors (status_code >= 500) are sprinkled so error-rate and filter logic are meaningful:
  - comp_A has three server errors (ids 5, 12, 19).
  - comp_B has two server errors (ids 25, 30).
  - comp_D has one server error (id 49).
  - comp_E has one server error (id 58) but note id 58 also has malformed timestamp.
  - comp_C has no server errors (0 entries >=500).

4) Grader guidance / traps and common errors
- Timestamp parsing:
  - Some candidates may ignore malformed timestamps and include them as-is (which will distort per-day grouping) or may attempt to coerce malformed formats. The exam requires the candidate to explicitly state how they handled malformed timestamps; accept either dropping or converting if conversion is clearly documented and reproducible.
- Numeric coercion:
  - Some candidates may coerce "NaN" or "abc" to 0. This is acceptable only if explicitly justified; more typical (and safer) choice is to treat non-numeric metric_value as missing and exclude from numeric aggregations. The rubric allocates points for explicit handling.
- Inclusion consistency:
  - The candidate must be consistent: if they drop a row in Step 1 due to malformed timestamp, later queries and transformation must operate on the same cleaned data.
- Join with lookup:
  - components_lookup.csv is provided. If a candidate instead invents a different mapping, accept only if they declare it in assumptions; prefer using the provided lookup.
- Expected verification:
  - Evaluator can re-run candidate SQL/scripts and compare counts:
    - Total rows in CSV = 60 (verifiable).
    - Malformed metric rows: ids 7, 18, 55.
    - Malformed timestamp rows: ids 10, 58.
    - Per-day counts: if the candidate drops malformed timestamps, expect 2025-01-10 => 51 and 2025-01-11 => 7.
    - Top-5 by average: ordering comp_A, comp_B, comp_D, comp_C, comp_E should hold given reasonable cleaning choices.

5) How these materials differentiate practical ability
- The dataset is small enough to process in 90 minutes but contains realistic issues: malformed timestamps and non-numeric metrics that require practical cleaning choices.

- Decisions that affect outputs (drop vs coerce) are intentionally embedded so the evaluator can score rationale and reproducibility, not just numerical answers.
