### Exam Title
CSV Summarizer — Implementation, Revision, Comments, and Documentation (Basic Practical Exam, 90 minutes)

### Instructions for Candidate
You have 90 minutes total. Use the provided computer, code execution environment, and text editor only. Do not use the internet or other external materials.

High-level steps and suggested time:
- 0–10 min: Read these instructions and inspect provided files (data.csv).
- 10–50 min (Task A): Implement the initial CLI program that reads data.csv and writes a JSON summary.
- 50–75 min (Task B): Implement the required revision (group-by feature) and update code/comments.
- 75–90 min: Produce README, changelog, capture outputs, and package everything into test_submission.json.

You may choose one language: Python, Java, or C. Use the exact filenames below for your chosen language:
- Python: summarizer.py
- Java: Summarizer.java
- C: summarizer.c

Do not rename these files.

Task A — Core implementation (required)
1. Implement a command-line program named as above (depending on language) that:
   - Accepts: data.csv as the first positional argument.
   - Optional flag: --output <file> (if omitted, write JSON to stdout).
   - Reads data.csv (CSV with header row).
   - Computes summary statistics for each numeric column: count, sum, mean, min, max.
     - Numeric columns for this exam are: value1 and value2 (the provided data.csv will include columns: id, group, value1, value2).
     - count: integer number of non-empty numeric cells included in calculations.
     - sum/mean/min/max: numeric values formatted with exactly two decimal places (e.g., 12.34). If a column has count 0, set sum/mean/min/max to null.
   - Behavior for missing/invalid cells:
     - Empty cells (blank) in numeric columns must be ignored (not counted).
     - If a non-empty, non-parseable value appears in a numeric column, the program must print a clear error message to stderr naming the row number and column, exit with non-zero status, and produce no JSON output file.
   - If the input file is missing or unreadable, print a clear error message and exit non-zero.
   - Output JSON structure (see "Expected Outcome" below) with stable ordering:
     - For the top-level "summary" object: numeric column keys must be sorted alphabetically.
     - For group-by output (Task B): group keys must be sorted lexicographically ascending.

Task B — Revision / feature addition (required)
2. Modify the program to add an optional flag:
   - --group-by <column_name>
   - When provided, compute the same per-numeric-column summaries separately for each distinct value in the group-by column.
   - Output JSON must then include a top-level "groups" object mapping each group value (string) to that group's per-column summary object (same format as Task A for each group). Group keys must be sorted.
   - If the group-by column does not exist, print a clear error message and exit non-zero.

Comments and documentation (required)
3. While implementing:
   - Add a top-of-file header comment describing the file purpose.
   - Provide docstrings (or equivalent comments) for each top-level function or non-trivial block.
   - Add inline comments explaining any non-obvious logic.
4. Create a README (README.md) describing:
   - One-paragraph project purpose.
   - Exact, copy-pasteable run commands for Task A and Task B for your language.
   - Any assumptions you made.
   - How you format numeric output (two decimal places) and numeric tolerance if applicable (not required).
5. Create a changelog (CHANGELOG.md) with at least two entries:
   - Initial implementation — short description and files changed.
   - Revision — description of group-by feature and files changed.

Capturing outputs (required)
6. Run and capture outputs (for the provided data.csv):
   - Task A command (primary): produce out_initial.json (exact file).
   - Task B command (revision): produce out_groupby.json (exact file).
   - Include the exact run commands you used in the submission.

Time and constraints
- Complete everything in 90 minutes.
- You may assume the provided data.csv has no invalid numeric cells for the main scenario, but your program must still implement invalid-cell detection as specified.

Allowed tools
- Code execution environment (run/compile code).
- Text editor.

### Expected Outcome
By the end of the exam you must produce:
1. A working CLI program (summarizer.py, Summarizer.java, or summarizer.c) that implements Task A and Task B behavior.
2. Inline comments and docstrings/top-file header as specified.
3. README.md containing purpose, exact run commands, assumptions, and formatting decisions.
4. CHANGELOG.md with at least two entries (initial and revision).
5. Two JSON output files produced from the provided data.csv:
   - out_initial.json — result of Task A
   - out_groupby.json — result of Task B (grouped by the "group" column)
6. A single JSON wrapper named test_submission.json containing all deliverables (see Submission Format below).

Exact JSON output structure requirements (must match exactly):
- Task A (no group-by) output: a JSON object containing exactly one key "summary".

Example structure (keys and ordering rules described above):
{
  "summary": {
    "value1": { "count": 12, "sum": 123.45, "mean": 10.29, "min": 1.00, "max": 20.00 },
    "value2": { "count": 12, "sum": 234.56, "mean": 19.55, "min": 2.00, "max": 25.00 }
  }
}

- Task B (with --group-by group) output: a JSON object containing exactly one key "groups".

Example structure:
{
  "groups": {
    "A": {
      "value1": { ... },
      "value2": { ... }
    },
    "B": {
      "value1": { ... },
      "value2": { ... }
    }
  }
}

Formatting and ordering rules:
- Numeric values in JSON must be represented with exactly two digits after the decimal point (e.g., 3.00, 0.00). Use null for missing numeric aggregates (when count is 0).
- In "summary" object, numeric column keys sorted alphabetically ascending.
- In "groups" object, group keys sorted lexicographically ascending.
- Use JSON null (not string) for null aggregates.

Validation behavior:
- For any non-empty cell in value1 or value2 that is not a valid number, program must print an error to stderr with row number and column name and exit non-zero (no JSON written).
- If data.csv is missing, print a clear message and exit non-zero.

Exact run commands required in README and test_submission.json:
- Python:
  - Task A primary_run_command: python3 summarizer.py data.csv --output out_initial.json
  - Task B revision_run_command: python3 summarizer.py data.csv --group-by group --output out_groupby.json
- Java:
  - Build: javac Summarizer.java
  - Task A: java Summarizer data.csv --output out_initial.json
  - Task B: java Summarizer data.csv --group-by group --output out_groupby.json
- C:
  - Build: gcc summarizer.c -o summarizer
  - Task A: ./summarizer data.csv --output out_initial.json
  - Task B: ./summarizer data.csv --group-by group --output out_groupby.json

(Include the exact commands you used in test_submission.json fields primary_run_command and revision_run_command.)

### Provided Materials
You will be given one file:
- data.csv — a CSV file with header row and about ~20 rows. The header is:
  id,group,value1,value2
- The CSV contains integer id, string group (categorical), and numeric columns value1 and value2. Some cells may be blank. The provided file will not contain invalid non-numeric strings in numeric columns for the main test data, but your program must still detect and handle such cases if present.

No starter code is provided. Start from an empty project.
