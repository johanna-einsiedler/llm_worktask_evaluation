Notes on how these numbers were computed (verifiable steps)
- For each numeric column, ignore blank cells entirely.
- count = number of non-blank, successfully parsed numeric cells.
- sum = arithmetic sum of those numeric values.
- mean = sum / count, rounded to two decimal places in final JSON.
- min and max computed among the included numeric values, expressed with two decimals.
- All numeric fields are JSON numbers formatted with two digits after the decimal point (not strings).
- If count = 0 then sum, mean, min, max must be JSON null.

- Formatting numbers with more or fewer than two decimal places.
- Emitting numeric aggregates as JSON strings instead of numbers.
- Not preserving the required key ordering: summary keys must be alphabetically sorted; group keys lexicographically sorted.
- Off-by-one row numbering in error messages (the rubric expects a clear indication of row and column when encountering non-parseable numbers; many candidates count rows starting at 1 instead of counting header as row 1—either approach is acceptable as long as the error message is clear and consistent, but the evaluator should check that the reported row corresponds logically to the CSV line).

- Not implementing the --output flag behavior (writing file vs stdout) or not implementing --group-by behavior or checking for missing group-by column.
