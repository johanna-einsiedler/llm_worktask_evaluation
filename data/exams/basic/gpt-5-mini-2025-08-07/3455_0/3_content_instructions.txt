### Exam Title
Basic Practical Exam — Telemetry Ingest, Storage, Querying, and Reporting (90 minutes)

---

### Instructions for Candidate

You have 90 minutes to complete this practical exam. Use only the tools available in the environment: a code execution environment and a text editor. Do not use the network or non-standard libraries. Python 3 is recommended and available; if you use another language, it must be runnable in the provided environment and use only its standard library.

Place all code and artifacts in the exam root folder. You will be provided with input files (see Provided Materials). Your deliverable is a single JSON file named test_submission.json (see Submission Format). You may also include your scripts and the created DB file with your submission so an evaluator can re-run your work, but the grader will primarily read test_submission.json.

Follow these step-by-step tasks exactly.

Task 1 — Setup & Ingest (25 minutes)
- Create a file-backed database named telemetry.db in the exam root (SQLite is recommended and expected).
- Design one or more tables to store the telemetry rows from telemetry.csv. Create any indices you find useful (e.g., on host and timestamp).
- Implement an ingest script (single script/CLI entrypoint of your choice) that:
  - Reads telemetry.csv.
  - Parses and normalizes each row:
    - Parse timestamps into a proper datetime value.
    - Convert numeric fields to numeric types.
    - Handle missing/malformed values by either coercing (e.g., empty numeric → NULL) or skipping the row.
    - Detect and handle duplicate rows (your strategy must be consistent, documented in schema_description).
  - Inserts valid rows into telemetry.db.
  - Tracks rows_loaded and rows_skipped.
- The ingest operation must be reproducible by running your entrypoint command (see Run Instructions below).
- The DB file created must be named telemetry.db (put this path in your JSON submission).

Task 2 — Query & Analysis (30 minutes)
- Using the DB you created, produce the following query results and record them in test_submission.json:
  Q1. total_rows: Total number of rows present in the DB after ingest.
  Q2. top_hosts_by_avg_cpu: The top 3 hosts by average cpu_percent across the entire dataset. For each item return { host: string, avg_cpu: number } sorted descending by avg_cpu.
  Q3. hourly_stats_for_host: For a single host specified in the provided file target_host.txt, compute time-windowed hourly aggregates for the most recent 24 hours in the dataset (or fewer if the dataset has less than 24 hours):
     - For each hour window (hour-start timestamp in ISO8601), compute average CPU (avg_cpu) and peak memory (max_mem_mb).
     - Return up to 24 hour buckets in chronological order (oldest first).
     - Each item: { hour_start: ISO8601 string, avg_cpu: number, max_mem_mb: number }.
  Q4. cpu_spike_periods: Identify periods for any host where cpu_percent > 90 for at least 3 consecutive samples (consecutive means successive recorded samples for that host ordered by timestamp with no intervening sample below or equal to 90). For each period return { host: string, start_ts: ISO8601 string, end_ts: ISO8601 string }. If multiple distinct spike sequences exist for the same host, include them all.

- Make sure numeric outputs are numbers (not strings) and timestamps are ISO8601 strings.

Task 3 — Insert Single Record & Recompute (15 minutes)
- A single new telemetry record will be provided in insert_record.json. Implement a function/command in your script to insert that record into telemetry.db (after validating/parsing it the same way you did for the CSV).
- After insertion, re-run the relevant aggregation for the host in target_host.txt and return the updated average CPU for that host in the JSON output field updated_avg_cpu_for_host. Also indicate inserted_record_ok: true/false depending on whether the insertion succeeded.

Task 4 — Short Explanation & Recommendations (10 minutes)
- In test_submission.json include:
  - A 1–4 sentence schema_description that explains your table(s), column typing, and any normalization choices (e.g., flat table vs normalized host table).
  - Two brief, practical suggested_improvements you would make in a production system (e.g., partitioning, retention, batching, monitoring).

General requirements
- Provide a single runnable entrypoint command (e.g., python3 run_exam.py) and include that exact command as run_instructions in test_submission.json.
- Test_submission.json must follow the exact schema described below (Submission Format) so automated graders can parse it.
- Do not require any external packages; only use the standard library for your language.
- Keep your code readable and include minimal comments explaining non-obvious choices.
- Record any non-fatal warnings encountered during execution in the optional errors array in the submission JSON.

### Expected Outcome

By the end of the exam you must produce:
- A runnable script/CLI in the exam root that:
  - Creates telemetry.db and loads telemetry.csv.
  - Performs the queries and the insertion.
  - Produces the values required for test_submission.json.
- A JSON file named test_submission.json exactly matching the Submission Format below and containing all required fields and numeric results.
- Optionally include your telemetry.db and your scripts alongside test_submission.json so the evaluator can re-run your process. The primary artifact for grading is test_submission.json.

All numeric results should be numbers (floats/integers). Timestamps must use ISO 8601 strings (e.g., "2020-05-10T14:00:00Z" or timezone-aware equivalents). Two decimal places of precision for averages is acceptable.

### Provided Materials

You will be given the following files in the exam root:
- telemetry.csv — CSV file containing system telemetry rows (columns include at minimum: timestamp, host, cpu_percent, mem_mb, disk_io_kb, net_io_kb, event_type). The dataset contains a few controlled edge cases (a few missing CPU fields, one duplicate row, one malformed timestamp).
- target_host.txt — a plain text file containing exactly one host name. Use this host for Q3 and to compute updated_avg_cpu_for_host after insertion.
- insert_record.json — a JSON file containing one telemetry record to be inserted in Task 3. It matches the same columns as telemetry.csv.

Do not assume any other files exist. The evaluator will provide those three files packaged with the exam.

### Submission Format

You must create a single JSON file named test_submission.json with the exact fields and structure below. Field names and nesting must match exactly. Numeric values must be JSON numbers. Timestamp strings must be ISO8601.

Top-level fields:
- candidate: { name: string, email: string (optional) }
- env: { language: string, entrypoint: string, db_file: string }
  - language: e.g., "python3"
  - entrypoint: the exact command or filename you expect the grader to run (must match run_instructions)
  - db_file: the path to telemetry.db you created (e.g., "telemetry.db")
- ingestion: { rows_loaded: integer, rows_skipped: integer, note: string (optional) }
- results:
  - total_rows: integer
  - top_hosts_by_avg_cpu: [ { host: string, avg_cpu: number } ]   (array length must be 3)
  - hourly_stats_for_host: [ { hour_start: ISO8601 string, avg_cpu: number, max_mem_mb: number } ]   (up to 24 items)
  - cpu_spike_periods: [ { host: string, start_ts: ISO8601 string, end_ts: ISO8601 string } ]
- after_insert:
  - inserted_record_ok: boolean
  - updated_avg_cpu_for_host: number
- schema_and_choices:
  - schema_description: string  (1–4 sentences)
  - suggested_improvements: [ string, string ]  (exactly two short suggestions)
- run_instructions: string (the exact shell command(s) to run your solution from the exam root; one or two lines)
- optional: errors: [ string ] (any non-fatal warnings, optional)
