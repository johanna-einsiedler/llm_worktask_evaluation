Traps, common errors, and evaluator guidance
- Timestamp parsing mistakes:
  - A common error is failing to normalize timezone offsets (e.g., treating "2025-10-11T13:30:00+01:00" as 13:30Z rather than converting to 12:30Z). The correct behavior is to convert all timestamps to a single timezone (UTC) before filtering into windows.
- Deduplication mistakes:
  - Some candidates may forget to deduplicate duplicates. The duplicate for hostB at 2025-10-12T10:00:00Z is present; expected behavior is to deduplicate by (hostname, normalized_timestamp) and keep the first occurrence (documented in ingestion code and README).
- Missing values in aggregates:
  - Candidates should store NULLs for missing cpu_percent or mem_percent and exclude NULLs from average/peak calculations. Including NULLs as zeros will distort averages and should be flagged by the grader as incorrect.
- Hosts cross-reference:
  - Candidates must decide whether Q4 includes hosts present only in telemetry (hostX) and inventory-only hosts (hostD, hostF). The intended scoring accepts counting across the union of inventory and telemetry hosts; candidates should document their choice. The dataset is designed so all reasonable choices (inventory-only focus or union) will show low completeness; the grader should accept either approach if documented and consistent.
How these materials distinguish practical skill from pure theory
- A candidate who only knows concepts might write SQL or pseudo-code but fail to:
  - normalize and parse the timestamp variants,
  - deduplicate correctly, or
  - handle missing numeric values properly.
- A practical candidate will provide:
  - an ingestion script that normalizes timestamps to UTC, inserts NULL for missing numeric fields, deduplicates by (hostname, timestamp), creates sensible schema and indexes, and documents choices; and
  - SQL queries that use the dataset's max timestamp as "now", apply correct WHERE clauses for time windows, and compute aggregates excluding NULLs.
Acceptable grader tolerances
- Numeric rounding: the grader should allow reasonable floating-point formatting differences (e.g., 77.1666667 vs 77.1666666667). Candidates should return numeric values; string formatting of numbers is not acceptable.
- Query inclusion of hosts with no data: accept either excluding hosts with no telemetry from Q1/Q2 results or showing them with NULLs, provided the approach is documented in the README and scripts.
