### Exam Purpose
Confirm that the candidate can, in a realistic systems-software context, perform the end-to-end work of (1) ingesting operational system data, (2) storing it in a local data store suitable for analysis, (3) retrieving and manipulating it to produce metrics that support system capability and requirements analysis, and (4) produce reproducible outputs and brief recommendations. The exam verifies practical ability, not just conceptual knowledge.

Intended real-world capability demonstrated:
- Turning raw system telemetry / inventory / logs into a usable analytic dataset.
- Designing a minimal data model and implementing it.
- Writing reproducible ingestion and query code.
- Producing metrics and a short analysis that can be used to inform design/requirements decisions.

### Core Competencies
The basic exam tests whether the candidate can reliably do the following at an entry level:
- Parse and validate typical system data (CSV/JSON/text logs).
- Create and populate a lightweight local data store (SQLite) using a practical schema.
- Write correct SQL queries to retrieve aggregates and filtered results for analysis.
- Compute aggregate metrics (counts, averages, percentiles, time-window summaries).
- Handle common data issues (missing values, inconsistent timestamps, duplicates).
- Produce reproducible scripts and a small, clear results artifact (JSON summary + brief recommendations).
- Provide brief, clear documentation of how to reproduce their work.

### Recommended Structure
Total time: 90 minutes maximum.

Overview: 3 sequential hands-on tasks (ingest → query → analyze) plus packaging/README. Candidate submits a single JSON file "test_submission.json" (format specified below) containing code, outputs, and brief explanations. The exam creator will provide sample input files (small, representative dataset, see Practical Elements).

Task 1 — Data ingestion and storage (30 minutes, 35%):
- Provided: two small files:
  - systems.csv — inventory of hosts (hostname, cpu_cores, memory_gb, storage_gb, os_version, created_at)
  - metrics.log — timestamped telemetry lines (hostname, timestamp, cpu_percent, mem_percent, io_wait_ms)
- Candidate must:
  - Design a reasonable SQLite schema to store both inventory and time-series telemetry.
  - Write a short ingestion script (Python 3 recommended) that parses the provided files and populates an SQLite DB file named systems_metrics.db.
- Deliverable: ingestion script source included in test_submission.json and evidence that the DB contains expected tables (a schema dump or PRAGMA output).
