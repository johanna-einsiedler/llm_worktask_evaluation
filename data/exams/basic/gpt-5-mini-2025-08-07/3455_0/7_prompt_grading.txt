### Exam Purpose
This basic practical exam verifies that a candidate can take raw system telemetry/log data, design a simple persistent schema, reliably store the data, retrieve and manipulate it to produce analysis-ready aggregates and reports, and provide reproducible, runnable code that performs these steps. In real world terms it confirms the candidate can perform the core job of collecting and preparing system metrics data to support capacity planning, performance troubleshooting, and requirements analysis.

Intended outcome: after running the candidate’s submission, an evaluator (or an automated grader) can confirm that the candidate’s code created a persistent store, executed expected queries and aggregations, handled simple data issues, and produced the requested outputs in the required JSON submission.

4. Indexing trade-off
   - Candidate may create indices to make queries faster. The evaluator inspects whether indices exist (PRAGMA index_list) and whether they are sensible (e.g., index on host + timestamp).
5. Time grouping and windowing
   - Require hourly aggregation and detection of consecutive-high CPU windows — forces correct time parsing and ordering logic.

   - Provide specific hosts and timestamps to check for expected output so the grader can automatically confirm correctness.

These strategic elements reveal mastery of practical skills rather than rote knowledge.
