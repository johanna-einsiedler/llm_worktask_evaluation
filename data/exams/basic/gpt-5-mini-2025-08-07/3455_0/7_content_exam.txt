### Exam Title
Systems Telemetry: Ingest, Store, Query, and Analyze (Basic Practical)

### Instructions for Candidate

Overview and time limit
- Total time: 90 minutes maximum.
- You must work only with the local tools available (Python 3, sqlite3, a text editor and code execution). No network access or external Python packages are allowed.
- Deliverables must be submitted in a single JSON file named exactly test_submission.json (structure required below).

Task summary (3 hands-on tasks + packaging)
- Task 1 — Data ingestion & storage (≈30 minutes)
  - Write a Python 3 script named ingest.py that:
    - Parses the supplied files systems.csv and metrics.log.
    - Creates (or replaces) a SQLite database file named systems_metrics.db.
    - Creates a reasonable schema that stores:
      - Inventory rows (systems.csv).
      - Time-series telemetry (metrics.log).
    - Populates the database with parsed data.
    - Handles data quality issues in a reasonable way (you must document your chosen handling in-code comments and in README):
      - Missing cpu_percent or mem_percent (acceptable choices: insert NULL, impute, or skip — you must choose and justify).
      - Inconsistent timestamp formats (your parser must tolerate the small variations in the provided data).
      - Duplicate telemetry records (same hostname + timestamp) — deduplicate by your chosen rule (keep first/last); document it.
      - Telemetry rows for hosts not in inventory — choose whether to insert a placeholder inventory row or leave telemetry with NULL foreign key; document your approach.
    - Create at least one index appropriate for querying typical telemetry by host and time (e.g., host + timestamp).
  - The script must use only Python standard library modules (e.g., csv, json, datetime, sqlite3, re, etc.).
  - The script must produce a SQLite DB file named systems_metrics.db in the current directory.

- Task 2 — Retrieval & analysis queries (≈30 minutes)
  - Write a script named queries.py (Python 3) that opens systems_metrics.db and runs the following SQL queries. Include the SQL text and exact results in your JSON submission.
    - Q1: Top 5 hosts by average cpu_percent over the last 24 hours.
    - Q2: Per-host average and peak (maximum) mem_percent for the last 7 days.
    - Q3: Inventory hosts where memory_gb < RECOMMENDED_MINIMUM_MEMORY_GB (constant below).
    - Q4: Count telemetry samples per host and flag hosts with < EXPECTED_COMPLETENESS_THRESHOLD% of expected samples in the last 24 hours (expected cadence below).
  - Details used for queries (fixed constants — use these exact values):
    - RECOMMENDED_MINIMUM_MEMORY_GB = 8
    - EXPECTED_SAMPLING_INTERVAL_MINUTES = 5 (i.e., one telemetry sample every 5 minutes per host)
    - EXPECTED_COMPLETENESS_THRESHOLD = 95 (percent)
  - Time windows: define "last 24 hours" and "last 7 days" relative to the maximum timestamp present in metrics.log (i.e., treat the dataset's max timestamp as "now"). Use ISO-8601 timestamps for any displayed timestamps in results.

- Task 3 — Simple manipulations to inform requirements (≈20 minutes)
  - Using SQL or simple Python post-processing of query results, compute:
    - A short list (hostname + measured values) of hosts that are "capacity-constrained", defined for this exam as:
      - average cpu_percent over last 24 hours > 75, OR
      - average mem_percent over last 7 days > 80 AND memory_gb < 8
    - Counts:
      - total number of distinct hosts in inventory.
      - number of hosts flagged with low telemetry completeness in Q4.
    - Produce one concrete recommended requirement change (one-line recommendation plus one short justification paragraph) based on observed metrics. Example acceptable recommendations: raise minimum memory to X GB, increase sampling cadence to Y seconds/minutes, provision N extra CPU cores for a group of hosts, or require monitoring changes. Your recommendation must reference the computed numeric metrics.

- Packaging & Reproducibility (≈10 minutes)
  - Provide a README string explaining exact commands to reproduce the DB and run the queries.
  - All code must be runnable locally without modification using only Python 3 and sqlite3.

Additional instructions (must follow)
- Script filenames required: ingest.py and queries.py. Your ingest.py must create systems_metrics.db in the working directory. queries.py must open systems_metrics.db and produce outputs used in the submission JSON.
- Document any non-trivial choices (missing data handling, deduplication rule, hosts mismatch) in:
  - brief comments in your scripts, and
  - the README field in the submission JSON.
- Use ISO-8601 for any timestamps in your outputs and in the JSON fields.
- Do not include binary files; you must embed script sources and results inside test_submission.json as strings and arrays (structured JSON). The grader will not accept separate script attachments.

### Expected Outcome

By the end of the exam you must produce:
- A working ingestion script ingest.py that creates systems_metrics.db from the provided datasets.
- A query script queries.py that runs the 4 required queries and computes the simple analysis for Task 3.
- A single JSON file named test_submission.json (structure required below) that includes:
  - Candidate contact info and environment info.
  - The full source code of ingest.py and queries.py as string fields.
  - A schema dump (PRAGMA table_info or .schema output) describing the created tables and indexes (array of strings).
  - The exact SQL text for each required query and the exact result rows produced by running those queries against systems_metrics.db (results must be exact numeric values/strings).
  - The computed metrics and capacity-constrained host list.
  - One concrete recommendation with a short justification referencing the numeric metrics.
  - README string with exact commands to run ingest.py and queries.py to reproduce all outputs.
- All outputs must be reproducible by running the commands in the README on a machine with Python 3 and sqlite3, using only the supplied data files.

### Provided Materials

You will be given two files (placed in the working directory):
1. systems.csv — inventory of hosts (columns: hostname, cpu_cores, memory_gb, storage_gb, os_version, created_at)
2. metrics.log — line-delimited telemetry (each line is JSON or CSV; contains fields hostname, timestamp (ISO-8601 with a few small format variations), cpu_percent, mem_percent, io_wait_ms)

Data quality characteristics intentionally present in the provided files (you must handle them):
- A small fraction of telemetry rows are missing cpu_percent or mem_percent.
- Some timestamps use slightly different ISO-8601 variants (e.g., timezone offsets or missing seconds).
- A few duplicate telemetry rows exist (same hostname + timestamp).
- Some hosts appear in telemetry but not in inventory, and some inventory hosts have no telemetry.

Provided constants you must use in queries and analysis (do not change):
- RECOMMENDED_MINIMUM_MEMORY_GB = 8
- EXPECTED_SAMPLING_INTERVAL_MINUTES = 5
- EXPECTED_COMPLETENESS_THRESHOLD = 95 (percent)
- Time windows are relative to the maximum timestamp found in metrics.log.
