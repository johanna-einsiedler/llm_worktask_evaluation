### Exam Title
Practical: Run, Verify, Test, and Patch a Small Python Program (Basic, 90-minute)

### Instructions for Candidate
You have 90 minutes and access only to: a computer with a code execution environment (Python 3) and a text editor. No internet or external packages are available. Use only the provided files and standard Python 3.

You must perform three hands-on tasks in sequence. Do not modify the provided code for Task 1. Capture real console output and include exact commands and timings. You will embed any new or modified source or test files inside the final JSON submission file named test_submission.json (see Submission Format below). test_submission.json is the only file that will be used for evaluation.

Follow these steps exactly:

1. Setup (first 5 minutes)
   - Unpack the provided materials into a working directory.
   - Inspect files but do not change any source files yet.
   - Note the filenames of the provided program(s) and input data.

2. Task 1 — Run & Reproduce (20 minutes)
   - Objective: Run the original, unmodified program using the provided input file(s) and reproduce the expected output (an expected output file is provided).
   - Actions:
     - Execute the program with the exact command(s) required to produce the output.
     - Capture the complete standard output and standard error, and the exit code.
     - Compare produced output to the provided expected output byte-for-byte.
   - Required evidence (to include in JSON under task T1):
     - commands_executed: array of exact shell commands you ran (in order).
     - raw_console_output: the full console output you saw (stdout + stderr).
     - exit_code: numeric exit code from the process.
     - expected_output_match: one of "yes" | "no" | "partial".
     - difference_note: brief note describing differences if not an exact match.
     - time_spent_minutes: integer (approximate minutes spent on Task 1).

3. Task 2 — Automated Checks (30 minutes)
   - Objective: Create and run a small automated test harness that verifies key behaviors of the program. Tests must be runnable with a single command.
   - Constraints:
     - Use only Python 3 standard library for tests (no pytest dependency). Provide a single entry-point command such as: python run_tests.py
     - Write at least 3 meaningful checks that capture core behavior (including the behavior verified in Task 1). Tests may be simple assertions that print PASS/FAIL or exit non-zero on failure.
   - Actions:
     - Add test files to your working directory (you will embed these files in the JSON).
     - Run the test command and capture full output and exit code.
   - Required evidence (to include in JSON under task T2):
     - test_files: object mapping filename -> file contents (text).
     - test_command: the exact command used to run tests (single string).
     - test_output: full console output from running the tests.
     - tests_passed: integer number of tests that passed (as reported by your harness).
     - tests_failed: integer number of tests that failed.
     - coverage_note: short description of what each test checks.
     - time_spent_minutes: integer (approximate minutes spent on Task 2).

4. Task 3 — Diagnose & Fix (30 minutes)
   - Objective: Diagnose a seeded bug or ambiguity and make a minimal, correct patch. Re-run the original program and your test harness to demonstrate the fix.
   - Constraints:
     - Make minimal source edits (aim for 1–15 lines changed). If you choose to change the run instructions rather than code, document and justify that decision.
     - Provide patched source files embedded in the JSON. Also include commands and logs for re-running Task 1 and Task 2 after the patch.
   - Actions:
     - Identify root cause (bug or ambiguous requirement).
     - Apply a minimal patch to source or adjust the instructions (document the choice).
     - Re-run the same commands from Task 1 and the test command from Task 2.
     - Capture outputs and exit codes as before.
   - Required evidence (to include in JSON under task T3):
     - root_cause: short description (one or two sentences).
     - patch_files: object mapping filename -> patched file contents (text). If multiple files were changed, include all changed files.
     - patch_summary: short note of what you changed and why (one paragraph).
     - commands_executed_after_patch: array of exact commands you ran after the patch (in order).
     - post_patch_console_output: full console output from the re-run of Task 1 after patch.
     - post_patch_test_output: full console output from the test harness after patch.
     - post_patch_exit_codes: mapping command -> numeric exit code (for the commands you ran after patch).
     - final_status: one of "fixed" | "partially_fixed" | "not_fixed".
     - decision_justification: if you changed code vs. instructions explain why (one paragraph).
     - time_spent_minutes: integer (approx. minutes spent on Task 3).

5. Finalize & Submit (up to 10 minutes, within total 90 minutes)
   - Assemble all required evidence into a single JSON file named test_submission.json exactly. See Submission Format for required schema and rules.
   - Do not submit other files separately — everything the evaluator needs must be inside test_submission.json.
   - Ensure timestamps are ISO8601 and that time_spent_minutes across tasks plausibly sum to ≤ 90.

Important general rules
- Do not use any external packages or internet resources.
- Do not change file names of the provided files unless you note the original name and include both original and modified copies in the JSON.
- Tests must run with a single command. The evaluator will run the same command(s) you provide.
- Be concise but provide all required fields; missing fields may mean lost points.

Recommended time allocation (suggested, but you manage your own time)
- Setup & Task 1: 20 minutes
- Task 2: 30 minutes
- Task 3: 30 minutes
- Finalize JSON: 10 minutes (can overlap)

### Expected Outcome
By the end of the 90 minutes you must provide a single JSON file named test_submission.json that contains:

- Candidate metadata: name, candidate_id, start_time, end_time.
- Complete evidence for Task 1, Task 2, Task 3 as specified above, including:
  - Exact commands you ran (so the evaluator can re-run them).
  - Raw console logs (stdout+stderr) and numeric exit codes for commands.
  - All test files and any patched source files embedded as text values.
  - Clear short explanations/diff notes for any fixes or decisions.
- A short self_evaluation with a confidence rating (1–5) and notes.
- Total time_spent values that are plausible and sum to ≤ 90 minutes.

Evaluation will check:
- You ran the original program and reported exact results.
- You implemented and executed automated checks with a single command.
- You diagnosed and minimally fixed the seeded bug and demonstrated passing tests and correct output after the fix.
- Your JSON is complete, correctly formatted, and reproducible.

Be precise — Task 1 expected output must match the provided expected-output file byte-for-byte unless you explicitly document why a difference is acceptable.

### Provided Materials
You will be given a ZIP or directory containing:
- program.py — the main program (Python 3, single-file or small 2–3 file codebase). (Do not edit this file before Task 1.)
- input_primary.txt (or .csv/.json) — input data to run with program.py for Task 1.
- expected_output.txt — the canonical expected output for Task 1 (byte-for-byte match expected).
- input_extra.txt — a small extra input that exposes the seeded bug or ambiguity for Task 3.
- README-run.txt — minimal run instructions; one instruction will be intentionally ambiguous (document decisions you make).
Notes:
- All provided files are dependency-free and require only Python 3.
- No other files or dependencies are available.

### Submission Format
You must submit a single file named exactly test_submission.json. This JSON must be UTF-8 encoded and follow the schema below. The evaluator will not accept any other filenames or separate files.

Required top-level JSON schema (fields are required unless marked optional):

{
  "candidate": {
    "name": "string (full name)",
    "candidate_id": "string (alphanumeric)",
    "start_time": "ISO8601 timestamp (when you began the exam)",
    "end_time": "ISO8601 timestamp (when you finished)"
  },
  "tasks": [
    {
      "task_id": "T1",
      "title": "Run & Reproduce",
      "time_spent_minutes": number,
      "commands_executed": ["string", "..."],                // exact shell commands in order
      "raw_console_output": "string",                       // stdout + stderr captured
      "exit_code": number,                                  // numeric exit code from main run command
      "expected_output_match": "yes|no|partial",
      "difference_note": "string"                           // brief explanation if not exact
    },
    {
      "task_id": "T2",
      "title": "Automated Checks",
      "time_spent_minutes": number,
      "test_files": {                                       // include every test file you created
        "run_tests.py": "string contents",
        "test_helper.py": "string contents",
        "..." : "..."
      },
      "test_command": "string",                            // single command to run all tests
      "test_output": "string",                             // full stdout+stderr of test run
      "test_exit_code": number,                            // numeric exit code from test command
      "tests_passed": number,
      "tests_failed": number,
      "coverage_note": "string"
    },
    {
      "task_id": "T3",
      "title": "Diagnose & Fix",
      "time_spent_minutes": number,
      "root_cause": "string",
      "patch_files": {                                     // include modified source files here
        "program.py": "string contents",
        "other_file.py": "string contents",
        "..." : "..."
      },
      "patch_summary": "string",
      "commands_executed_after_patch": ["string", "..."],  // commands you ran after patch
      "post_patch_console_output": "string",               // re-run of Task 1 main run stdout+stderr
      "post_patch_test_output": "string",                  // test_command output after patch
      "post_patch_exit_codes": {                           // map command -> exit code
         "python program.py input_primary.txt": 0,
         "python run_tests.py": 0
      },
      "final_status": "fixed|partially_fixed|not_fixed",
      "decision_justification": "string"
    }
  ],
  "self_evaluation": {
    "confidence_level": "integer 1-5",
    "notes": "string (areas confident vs. uncertain)"
  }
}

Formatting and content rules (strict)
- All timestamps must be ISO8601 (e.g., "2025-10-12T13:45:00Z" or with offset).
- All file contents must be provided as plain text strings in their original encoding (UTF-8).
- Every command listed in commands_executed and commands_executed_after_patch must be executable by the evaluator as-is in the working directory after writing the embedded files to disk.
- test_command must be a single shell command string. Tests should run without editing by the evaluator.
- The evaluator will re-create the provided files from the embedded strings exactly as you submitted them and then run the listed commands to reproduce your logs.
- The total of time_spent_minutes across the three tasks should be ≤ 90. If they sum larger, provide a short note in self_evaluation explaining why.

Final note
- test_submission.json is the only file that will be evaluated. Make sure it contains every artifact and log the evaluator will need to reproduce your work. If you choose to alter run instructions rather than code, include the modified README-run.txt content in patch_files and justify the choice. Good luck.
