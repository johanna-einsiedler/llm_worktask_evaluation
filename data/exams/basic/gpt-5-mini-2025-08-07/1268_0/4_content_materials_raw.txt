File: program.py
#!/usr/bin/env python3
import sys

def main():
    if len(sys.argv) != 2:
        print("Usage: python program.py <input_file>", file=sys.stderr)
        sys.exit(2)

    input_path = sys.argv[1]
    # NOTE: This original file intentionally does not handle blank lines or
    # alternate delimiters robustly. Do not modify program.py for Task 1.
    with open(input_path, "r", encoding="utf-8") as f:
        lines = f.read().splitlines()

    total = 0
    count = 0
    top_score = -999
    top_id = ""

    for line in lines:
        # Deliberately naive parsing (seeded bug: will fail on empty lines or wrong delimiter)
        parts = line.split(',')
        id = parts[0]
        score = int(parts[1])
        total += score
        count += 1
        if score > top_score:
            top_score = score
            top_id = id

    avg = total / count
    print("Summary Report")
    print("Total records: {}".format(count))
    print("Average score: {:.2f}".format(avg))
    print("Top scorer: {} ({})".format(top_id, top_score))

if __name__ == "__main__":
    main()

How materials were constructed and why
- program.py: A short, dependency-free Python 3 script that reads a single input file (specified on the command line), parses each line as "ID,score", computes a total record count, the average score (printed with two decimals), and the highest-scoring record. It is deliberately small so candidates can inspect it quickly and make a minimal patch in Task 3.
- Seeded bug: program.py uses a naive parsing loop that calls line.split(',') without skipping empty lines or trimming whitespace; it assumes each non-empty line will split into at least two elements. input_extra.txt contains a blank line which will produce parts with length 1 and cause an IndexError (or ValueError when attempting int conversion). This forces the candidate to diagnose and apply a minimal and robust fix (e.g., skip empty lines and strip whitespace).
- Ambiguity: README-run.txt intentionally mentions comma-separated fields but also notes that some sources may use semicolons. This gives the candidate a decision point: either modify code to accept both delimiters or document that inputs must be comma-separated and update the instructions. The evaluator should accept either reasonable choice, provided the candidate justifies it.
- Primary input and expected output: input_primary.txt is small (5 rows) and deterministic. expected_output.txt contains the exact, byte-for-byte canonical output the original program should produce when run on input_primary.txt. The evaluator will compare the candidate's captured stdout to this file.
- Extra input: input_extra.txt is identical to the primary input but includes a blank line between records to trigger the seeded parsing failure. It is the minimal change needed to expose the bug.

Data patterns and relationships
- Each data row format: <RecordID>,<IntegerScore>
  - RecordID: string starting with "S" followed by three digits (e.g., S001).
  - IntegerScore: whole number (e.g., 78).
- Expected aggregate calculations:
  - Total records: count of valid data lines.
  - Average score: arithmetic mean printed with two decimal places.
  - Top scorer: the RecordID with the maximum integer score; in the provided primary dataset S004 has the highest score (95).

A common incorrect “fix” is to simply remove blank lines from the input; that is not allowed because candidates must preserve provided input files and instead should fix the code or update instructions (and document the decision).
- Another common mistake would be to over-engineer the patch (adding heavy parsing libraries or many lines). The expectation is a minimal change (1–15 lines), e.g., skip lines that are empty or whitespace and split on either ',' or ';' if the candidate chooses to accept both delimiters.
- Forgetting to capture and report exit codes, or failing to provide exact commands used, will reduce reproducibility and score.
- Tests: candidates must write their own run_tests.py (or similar) using only Python standard library — failing to do so or using external libraries will be scored down.
