### Exam Title
Update automated test scripts to ensure currency — Basic Practical Exam

---

### Instructions for Candidate

You have 90 minutes to complete this practical exam. Use only the tools available: the code execution environment (terminal) and a text editor. No internet access or external libraries are required.

Follow these steps exactly:

1. Start the timer and record your start time (ISO 8601). You will include this in the submission.
2. Run the test suite as provided to reproduce the initial failures.
   - Use the run command in the repository README (typically: python -m unittest discover).
   - Capture and copy the full raw console output (stdout/stderr) exactly as produced. Do not edit it.
3. Diagnose the failures.
   - From the console output and stack traces, identify why tests fail. The project includes two deliberately failing tests (different categories) and one small task requiring a new test.
   - Do not modify application code unless explicitly instructed by the test content — the goal is to update tests/fixtures only.
4. Update the test suite and/or fixtures so tests reflect the intended (changed) application behavior.
   - Make only the minimal, correct changes necessary so the tests again validate the application.
   - Allowed edits: test files under tests/ (rename, edit, add), fixtures/data files used by tests.
   - Disallowed edits: modifying application code files under app/ (except in an explicitly provided supporting instruction).
   - Keep tests readable and maintainable (clear assertions, avoid unnecessary complexity).
5. Add one small new test that covers a simple new acceptance rule or edge case (data-driven/parameterized or one more assertion variant). This should be concise (a few lines) and live in the tests/ folder.
6. Re-run the entire test suite. Capture and copy the full raw console output showing the final results.
7. Prepare your submission file test_submission.json (see Submission Format below).
   - Include your start and end times (ISO 8601), the raw initial and final test outputs, any modified file contents, brief rationales, and a short self-assessment.
8. Stop the timer and record your end time (ISO 8601). Ensure total time does not exceed 90 minutes.

Recommended time allocation (suggested, not enforced):
- Setup & initial run: 10–15 minutes
- Diagnose failures: 15–20 minutes
- Update tests & fixtures: 30–35 minutes
- Re-run and verify: 10–15 minutes
- Prepare submission JSON: 5–10 minutes

Notes:
- All console output you paste must be the literal output from running the tests in the provided environment.
- Make minimal targeted edits: exam grades favor focused changes to tests/fixtures rather than broad rewrites.
- If you encounter an unavoidable problem, document it clearly in the open_issues field.

### Submission Format

Produce a single file named test_submission.json at the repository root. It must be valid JSON and contain the following fields exactly:

- candidate_name (string) — your full name.
- start_time (string, ISO 8601) — when you began the exam.
- end_time (string, ISO 8601) — when you finished the exam.
- environment (string) — runtime info, e.g., "Python 3.9.2".
- initial_test_run (string) — full raw console output from the initial test run (copy-paste).
- final_test_run (string) — full raw console output after your edits (copy-paste).
- modified_files (array of objects) — one object per modified or added file; each object must have:
  - path (string) — relative path to the file you changed or added (e.g., "tests/test_main.py").
  - content (string) — the full content of the updated file (not a partial snippet).

import json

def greet(name):
    """
    New application behavior: greeting message includes the phrase 'Welcome back, ...'
    """
    return f"Welcome back, {name}!"

def load_user_from_fixture(path):
    """
    Load a user dictionary from a JSON fixture file at 'path'.
    Expected JSON structure (current application): {"username": "<name>", "status": "<status>"}
    """
    with open(path, "r", encoding="utf-8") as f:
        return json.load(f)

def is_active(user):
    """
    Returns True if user has status 'active'.
    """
    return user.get("status") == "active"

import os
import unittest
from app import main

class MainTests(unittest.TestCase):
    def _fixture_path(self, name="user.json"):
        # Path to fixtures relative to this file
        base = os.path.dirname(__file__)
        return os.path.abspath(os.path.join(base, "..", "fixtures", name))

    def test_greet_literal(self):
        # This test expects the old literal greeting. It will fail initially because the app greeting changed.
        self.assertEqual(main.greet("Alice"), "Welcome, Alice!")

    def test_load_user_schema(self):
        # This test expects a fixture key named 'user_name'. It will fail initially because fixture uses 'username'.
        user = main.load_user_from_fixture(self._fixture_path())
        self.assertEqual(user["user_name"], "Alice")

    def test_is_active(self):
        # A third test that should pass initially (status is 'active' in fixtures/user.json)
