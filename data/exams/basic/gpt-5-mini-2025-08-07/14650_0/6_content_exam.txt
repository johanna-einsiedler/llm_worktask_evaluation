### Exam Title
Maintaining and Updating Automated Tests (Basic Practical Exam — pytest + Python)

---

### Instructions for Candidate

Time limit: 90 minutes. You have a code execution environment and a text editor. Do not use any external resources. Do not modify any application code in src/ except when explicitly allowed below. Work only in the provided project.

Follow these steps in order:

1. Setup & initial verification (5–10 minutes)
   - Open the provided project folder.
   - Run basic environment/version checks you normally would (for example: python --version and pytest --version).
   - Run the test suite once (e.g., pytest -q or pytest -vv) and capture the full stdout and stderr from that run. Save the captured output for later inclusion in your submission.

2. Task A — Fix a failing assertion caused by a deliberate app change (approx. 20 minutes)
   - Inspect tests failing in the initial run and the application code under test (src/myapp.py).
   - Decide whether the failing test is due to an intentional change in application behavior (for this exam it is). Do not change application code to make tests pass — update the test instead.
   - Make the minimal, clear change to the failing test so it asserts the current, correct behavior of the application.
   - Re-run the tests and confirm the changed test now behaves as expected.

3. Task B — Stabilize a flaky/time-dependent test using deterministic technique (approx. 30 minutes)
   - Locate the flaky/time-dependent test (tests/test_timer.py).
   - Make the test deterministic by updating the test code only (e.g., use mocking/monkeypatching or fixtures to replace time-dependent functions). Do not add sleeps or change app code.
   - Ensure the test becomes reliable and reproducible.
   - Re-run the test suite and iterate until stable.

4. Task C — Add a new test for a minor feature/edge case (approx. 20 minutes)
   - Implement one small new test (or complete the provided test skeleton) that validates a minor new behavior in the application (tests/test_new_feature.py).
   - Follow the style of the existing tests and use available fixtures/monkeypatch if helpful.
   - Re-run the full test suite and make minimal edits until all tests pass.

5. Finalization & packaging (5–10 minutes)
   - Run the full test suite once and capture the complete stdout/stderr from that final run.
   - Prepare a single JSON file named test_submission.json with the required structure (see Submission Format below). The JSON must contain:
     - Candidate info and time spent.
     - Commands you ran.
     - Final pytest output (complete stdout/stderr).
     - Exact contents of every test file you changed or created (full file text).
     - A short change_log entry for each modified/added file that explains what you changed and why.
     - Environment info (Python and pytest versions if available).
   - Submit only the file test_submission.json.

Important constraints and rules
- Do not change application behavior in src/myapp.py. You may only edit tests and test helper files. (Minor helper code in tests is allowed.)
- The final pytest run included in your JSON must show all tests passing. If tests are not passing in your final output, this submission will be disqualified for this practical task.
- Keep changes minimal and well-justified in the change_log.
- The grader will reconstruct your modified files from the contents you include in modified_files, so include exact, runnable file contents.

Recommended commands you may use (examples):

Create and submit a single JSON file named test_submission.json. It must be valid JSON and must include these keys with these expected structures and types:

  - name: string
  - email: string
  - time_spent_minutes: integer (total minutes spent; must be <= 90)
- environment: object
  - python_version: string (output from python --version if available)
  - pytest_version: string (output from pytest --version if available)
- commands_run: array of strings
  - Ordered list of the shell commands you ran (e.g., ["python --version", "pytest -q"])

  - Complete stdout and stderr from your final pytest run (exact text).
- final_test_status: string
  - Short pytest pass/fail summary (e.g., "7 passed, 0 failed").

    - filename: string
    - line_range: optional string (e.g., "1-40") — optional; you may omit
    - short_description: string (1–2 sentence summary of the change)

  - Any additional comments, known issues, or follow-ups.

# small application module for the exam

import time

def greet(name: str) -> str:
    """
    Return a greeting for the given name.
    Current application behavior includes an exclamation mark.
    """
    return f"Hello, {name}!"

def wait_and_report(duration: float) -> float:
    """
    Sleep for `duration` seconds and return the measured elapsed time
    rounded to two decimal places.
    This intentionally uses time.time() and time.sleep() so tests that
    depend on exact timing must be made deterministic via test code.
    """
    start = time.time()
    time.sleep(duration)
    end = time.time()
    return round(end - start, 2)

def has_digit(s: str) -> bool:
    """
    Return True if the string contains at least one ASCII digit, otherwise False.
    """
    return any(ch.isdigit() for ch in s)
