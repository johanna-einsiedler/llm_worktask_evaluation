# Order Processor — Mini Spec (new behavior)

The SUT (app/orders.py) now uses the following behavior:
- Order dates are stored in ISO format `YYYY-MM-DD` in testdata/orders.json and the API returns dates in that format.
- Each order may now include an optional `status` field (e.g., `"processing"` or `"pending"`). If missing, it should be treated as `"pending"`.
- `format_order_summary(order)` now includes the status text at the end of the summary string: "... on {date} [status: {status}]".
- `calculate_total(order, include_discount=False)` returns the sum of (price * quantity) for items. If `include_discount=True`, subtract `order.get("discount", 0.0)` from the sum and round to 2 decimals.

Your tasks:
1. Run the test suite (command: `pytest -q`) and capture the failing output.
2. Diagnose failing/brittle tests and decide edits (tests only).
3. Update tests to match the new behavior and to be less brittle (no exact whole-dict equality, remove unnecessary sleeps, prefer contains/partial checks or key assertions).
4. Add one new pytest test to verify `calculate_total(..., include_discount=True)` works correctly for order `O1001`.
5. Re-run tests and produce a single `test_submission.json` as described in the exam instructions.

Run command example:
pytest -q

import json
import os

DATA_PATH_DEFAULT = os.path.join(os.path.dirname(__file__), '..', 'testdata', 'orders.json')

def load_order(order_id, data_path=DATA_PATH_DEFAULT):
    """Load an order dict by id from testdata/orders.json.
    New behavior: date is stored as ISO 'YYYY-MM-DD'; 'status' may be present.
    """
    with open(data_path, 'r', encoding='utf-8') as f:
        data = json.load(f)
    for o in data.get('orders', []):
        if o.get('id') == order_id:
            # return order dict as-is (status might be missing; callers should default)
            return o
    raise KeyError(f"order {order_id} not found")

def calculate_total(order, include_discount=False):
    """Calculate total for an order. If include_discount is True, subtract order.get('discount', 0.0)."""
    total = 0.0
    for item in order.get('items', []):
        total += item.get('price', 0.0) * item.get('quantity', 0)
    if include_discount:
        total -= order.get('discount', 0.0)
    return round(total, 2)

def format_order_summary(order):
    """Return a one-line summary for an order.
    New behavior: includes status at the end: [status: {status}]
    """
    order_id = order.get('id')
    customer = order.get('customer')
    date = order.get('date')  # ISO format YYYY-MM-DD in current data
    total = calculate_total(order)
    status = order.get('status', 'pending')
    return f"Order {order_id} for {customer}: ${total:.2f} on {date} [status: {status}]"

import time

    expected = {
        "id": "O1001",
        "customer": "Alice",
        "date": "01/15/2025",  # old MM/DD/YYYY format (legacy)

        "discount": 5.0,

    # brittle exact string expecting old date format and no status

def test_calculate_total_default():

How materials were constructed and intended candidate tasks
---------------------------------------------------------
I created a small deterministic Python repository (pure stdlib) with a concise SUT and a pytest test-suite that intentionally contains tests which no longer match the SUT's current behavior. The goal is for the candidate to run pytest, observe failing traces, decide appropriate test edits, make those edits (tests only), add one new test per README, and re-run pytest to demonstrate a green suite.

Key files and relationships
- app/orders.py (SUT)
  - load_order(order_id): reads testdata/orders.json and returns a dict (date is ISO YYYY-MM-DD; 'status' optional).
  - calculate_total(order, include_discount=False): sums price*quantity; subtracts discount when include_discount True (rounded to 2 decimals).
  - format_order_summary(order): returns "Order {id} for {customer}: ${total:.2f} on {date} [status: {status}]" (status defaults to "pending"). This is the "changed" behavior tests must accept.

- testdata/orders.json
  - Contains two deterministic orders, O1001 and O1002.
  - O1001: items configured so non-discount total is 37.50 and include_discount=True yields 32.50.

- tests/test_orders.py (initial test package provided to candidate)
  - Contains 5 tests. Several are intentionally brittle/legacy:
    - test_load_order_strict_keys expects a legacy `processed_at` key and old date format; this will fail because SUT no longer returns that key and date is ISO.
    - test_format_summary_exact expects the old date format and exact string without the new status suffix; fails due to date and extra status text.
    - test_brittle_sleep includes an unnecessary time.sleep and an exact format match; it will fail for the same reasons as format_summary.
    - test_calculate_total_default and test_discount_missing_flag assert totals (these should pass initially).
  - The candidate must:
    - Replace strict equality checks with focused key/assertions (e.g., verify essential keys exist, date has expected ISO value).
    - Update string assertions to use partial contains or regex or split checks to tolerate the new "[status: ...]" suffix and ISO date format.
    - Remove the sleep and any unnecessary delays.
    - Add a new test to confirm calculate_total(..., include_discount=True) yields 32.50 for O1001 (per README new requirement).

What failures/diagnosis the candidate will see
- Pytest failing tracebacks will point to:
  - dict equality mismatch in test_load_order_strict_keys (expected keys differ).
  - AssertionError comparing the exact strings in test_format_summary_exact and test_brittle_sleep.
- Candidates should deduce from the SUT code (app/orders.py) and README that:
  - Dates are ISO (YYYY-MM-DD) now.
  - format_order_summary includes status suffix.
  - calculate_total supports include_discount flag and should be tested when True.

- Candidates might remove the sleep but fail to update the exact string checks; ensure final assertions accept the "[status: ...]" suffix and ISO date.
