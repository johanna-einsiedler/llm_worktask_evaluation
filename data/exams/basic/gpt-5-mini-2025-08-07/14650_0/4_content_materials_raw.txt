src/async_ops.py
----------------
import threading

# Global flag to indicate event triggered
EVENT_FLAG = {"triggered": False}

def _set_event():
    EVENT_FLAG["triggered"] = True

def trigger_event_delayed(delay=0.05):
    """
    Start a background timer that will set EVENT_FLAG after `delay` seconds.
    Returns the Timer object.
    """
    t = threading.Timer(delay, _set_event)
    t.start()
    return t

def is_event_triggered():
    return EVENT_FLAG["triggered"]

import time

def test_trigger_event_immediate():
    """
    This test starts a delayed trigger and immediately checks the flag.
    It is intentionally fragile / failing in the current repo (no wait).
    Candidate should stabilize this test by adding a small wait/poll.

    # Start background trigger with a small delay
    trigger_event_delayed(delay=0.02)
    # Immediately assert event is set (this currently fails)
    assert is_event_triggered() == True

def test_trigger_event_with_wait():
    # Start background trigger and wait enough time for it to fire
    trigger_event_delayed(delay=0.02)

    assert is_event_triggered() == True

Overview of construction
- Purpose: small Python + pytest repository that contains 6 tests across 3 test modules. The SUT files (src/) intentionally contain small, realistic contract changes so tests fail. Candidate must change only tests/ files to make tests pass and stabilize one flaky test.
- Number of tests: 6 total

  - tests/test_inventory.py: 1 test (failing due to changed return type)

  - test_user_has_name: fails because SUT returns 'full_name' key instead of 'name' (rename)
  - test_inventory_summary_format: fails because SUT returns integer count instead of formatted string "N items" (type/format change)
  - test_trigger_event_immediate: fails because test asserts event is True immediately; the SUT uses a background Timer so event is only True after a delay (timing/flaky test)

Design rationale and patterns
- Renamed key pattern: Many real SUT changes rename fields. This tests candidate's ability to map failing assertion to a changed key and update tests accordingly, not to change SUT.
- Return type/format change pattern: Tests that assert types and exact formatting must be updated when SUT changes to preserve intent. Candidate should decide whether to update expected assertion or coerce as appropriate (prefer update to match SUT contract).
- Flaky/timing pattern: Asynchronous background side-effect via threading.Timer. The immediate-check test fails predictably in this repository. Candidate must stabilize by adding a short wait or polling loop in the test (not by removing or skipping the test). The other async test with explicit sleep shows the right approach and serves as a reference.
- Minimal edits: The tests are simple — candidate should only modify the test assertion lines and add at most a tiny helper in tests/ to poll/wait. They must not edit any src/ files.

Traps and common errors
- Editing src/ files: The README and instructions forbid changing SUT files. Some candidates may be tempted to change src/user.py to put back 'name' — this should be penalized if done.
- Overly broad fixes: Candidate might disable tests (e.g., xfail or comment out), or increase many global timeouts. The evaluation should ensure changes are minimal, targeted, and the intention is explained in diagnostics.
- Not resetting global state: src/async_ops.EVENT_FLAG is global. If a candidate modifies tests to rely on it, they should ensure tests remain independent (e.g., reset EVENT_FLAG in test). Acceptable minimal fixes: add a small loop/poll that checks is_event_triggered() for up to X ms, or use time.sleep(0.05). Better solution: poll with timeout and fail if not set. If a candidate forgets to reset EVENT_FLAG between tests they may create hidden order dependencies; evaluator should watch for that.
- Incorrect fix choices for inventory summary: Candidate can either change test to assert int value and meaningfully express expected result, or coerce SUT value to string in test before asserting. Preferred: change assertions to match SUT (assert isinstance(summary, int) and summary == 3) and add a comment.
