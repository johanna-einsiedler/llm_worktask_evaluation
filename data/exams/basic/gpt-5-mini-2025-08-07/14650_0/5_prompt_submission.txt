### Strategic elements (multi-step and decision points)
These elements help distinguish candidates who can actually perform the work:
- Diagnosis step: candidate must paste initial failing output. This tests ability to interpret stack traces and failing assertions.
- Decision point: whether to update test expectation or to modify fixture/data. The correct choice depends on whether the change represents an intentional application update (tests should change) or a regression (tests should assert older behavior). For the basic exam, the change should be clearly intentional and tests should be updated.
- Minimal-change principle: candidate should modify tests only as needed (not rewrite large chunks). Evaluate whether the edits are minimal and targeted.
- Maintainability decision: use stable selectors or keys in tests (prefer semantic IDs or keys). Candidate should show understanding by making changes that reduce flakiness (e.g., use a function to normalize whitespace rather than changing expected literal if appropriate).
- Data dependency: test fixture update may be required when the app returns a restructured JSON; candidate must update fixture and test assertions consistently.

import os
import unittest
from app import main

class MainTests(unittest.TestCase):
    def _fixture_path(self, name="user.json"):
        # Path to fixtures relative to this file
        base = os.path.dirname(__file__)
        return os.path.abspath(os.path.join(base, "..", "fixtures", name))

    def test_greet_literal(self):
        # This test expects the old literal greeting. It will fail initially because the app greeting changed.
        self.assertEqual(main.greet("Alice"), "Welcome, Alice!")

    def test_load_user_schema(self):
        # This test expects a fixture key named 'user_name'. It will fail initially because fixture uses 'username'.
        user = main.load_user_from_fixture(self._fixture_path())
        self.assertEqual(user["user_name"], "Alice")

    def test_is_active(self):
        # A third test that should pass initially (status is 'active' in fixtures/user.json)
        user = main.load_user_from_fixture(self._fixture_path())
        self.assertTrue(main.is_active(user))
