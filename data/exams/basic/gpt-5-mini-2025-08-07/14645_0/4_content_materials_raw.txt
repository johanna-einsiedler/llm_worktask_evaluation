How materials were constructed
- Compact, deterministic brief includes only the inputs required for planning: dates, environment lead times (with explicit usable offsets), team composition, automation capacity, dev SLA, UAT window, and 6 features (F1–F6) with clear priority/risk labels. These are the exact values candidates must use—no external data is required.
- The JSON schema summary restricts task fields and owners to the exact strings used by the evaluator to simplify automatic validation.

Key relationships and patterns (what candidates must reason about)
- Environment gating: Integration tests cannot run before offset 5; pre-prod tests must wait until offset 20. Candidates must set earliest_start_offset accordingly.
- Timeboxes: Code freeze (2025-11-21) and release (2025-11-28) create a finite testing window; tasks scheduled after code freeze must be non-code-impacting (e.g., documentation, reporting) or relate to pre-prod/performance.
- Defect cycles: Dev fix SLA is 2 business days — testers must include buffer days for defect triage, fix, and regression verification. Business days (Mon–Fri) should be used when estimating these cycles.
- Automation constraints: Automation owner can add up to 40% of regression during sprint and runs nightly 2 hours; this limits how much regression can be offloaded in schedule.
- UAT: 3 business days in final week implies testing/support must be available and defects triaged quickly in the last week.

Common candidate errors / traps
- Ignoring integration env provisioning and scheduling integration tests too early.
- Treating the 2-business-day dev SLA as calendar days, thereby underestimating defect cycles.
- Exceeding tester capacity by assigning two testers to full-day tasks plus overlapping tasks labeled parallelizable without splitting hours.
- Assigning Automation owner unrealistic full-day development time while also requiring nightly regression runs (automation owner capacity must respect the nightly 2-hour run expectation).
- Misplacing UAT support or failing to reserve time for UAT regression fixes before release.

What correct answers depend on
- Correct mapping of offsets to calendar dates using project_start_date.
- Inclusion of buffer days for defect triage and environment risk so code-freeze and release commitments are achievable.
- Realistic estimate_hours and duration_days that reflect two testers' capacity and the Automation constraints.
- Clear contingency plan that specifies which features/tests can be deferred (e.g., F4) or regression depth reduced.

How materials separate conceptual vs practical skill
- Practical scheduling constraints (offsets, two testers, automation limits, SLA) force candidates to produce concrete tasks, realistic durations, dependencies, and resource allocations rather than abstract descriptions. Good submissions will show critical-path thinking, buffer placement, and explicit trade-offs tied to these inputs.
