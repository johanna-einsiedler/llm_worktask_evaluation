### Strategic elements (distinguishing real performers)
The tasks are simple but include multi-step and decision points that reveal the candidate’s practical skills:

- Choice & reasoning for persistence: JSON vs SQLite. A candidate who chooses SQLite should show how to initialize the DB and perform safe updates. A candidate who chooses JSON should show atomic write (write-temp-rename) to avoid corruption — this demonstrates practical thinking about persistence.
- Validation and error handling: candidates must decide whether import rejects or merges duplicates; they must document the chosen behavior and implement it. Real performers will explicitly handle edge cases (e.g., numeric parsing errors, missing fields).
- Reproducible automation: candidates must create a demo runner that executes a defined scenario. Candidates who just implement functions but cannot script the scenario show weaker operational capability.
- Test coverage: small assertion tests are required. Candidates who provide meaningful tests that run automatically show they understand verification.
- Minimal concurrency-safety: basic file-locking or atomic write approach is a distinguishing, but optional, plus for candidates who implement it.

Decision points for candidates (they must document their choice in README/notes):
- How to store data (JSON vs SQLite). If JSON: how to avoid data corruption? If SQLite: ensure schema creation is idempotent.
- On import duplicates: overwrite, skip, or error? Candidate must pick and document behavior.
- Error reporting format (exit codes and stderr messages vs printing JSON error objects).
