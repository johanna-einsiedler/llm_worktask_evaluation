## Exam Overview and Purpose

This practical exam assesses a candidate's ability to systematically conduct trial runs of programs and software applications to verify they produce desired outputs and contain correct instructions. The exam simulates real-world scenarios where junior programmers must test, debug, and validate code before deployment.

**Key Assessment Goals:**
- Ability to execute systematic testing procedures
- Skills in identifying and documenting defects
- Competency in validating program outputs against requirements
- Proficiency in creating structured test reports

## Strategic Exam Design Elements

### 1. Multi-Step Testing Process
The exam requires candidates to follow a complete testing workflow:
- **Initial execution** to identify obvious errors
- **Systematic input testing** with various data scenarios
- **Output validation** against specified requirements
- **Documentation** of findings and recommendations

### 2. Realistic Code Scenarios
Three progressively complex programs simulate actual workplace situations:
- **Simple calculation program** with basic logic errors
- **Data processing script** with edge case handling issues
- **Multi-function application** with integration problems

### 3. Decision Points and Critical Thinking
Candidates must make judgment calls about:
- Severity classification of discovered issues
- Priority ranking for fixes
- Acceptance criteria for program readiness
- Risk assessment for deployment decisions

### 4. Data Relationship Understanding
The exam tests ability to:
- Trace data flow through program logic
- Identify input-output relationships
- Recognize data validation requirements
- Understand business rule implementations

## Practical vs. Theoretical Differentiation

### What Makes This Practical:
- **Hands-on execution**: Candidates must actually run programs, not just read code
- **Real debugging**: Finding actual errors in working (but flawed) code
- **Output analysis**: Comparing actual vs. expected results with real data
- **Documentation creation**: Producing professional test reports

### Strategic Elements to Identify Capable Candidates:

1. **Systematic Approach**: Qualified candidates will demonstrate organized testing methodology rather than random trial-and-error

2. **Edge Case Recognition**: Experienced testers naturally consider boundary conditions, invalid inputs, and unusual scenarios

3. **Root Cause Analysis**: Ability to trace errors back to specific code sections rather than just noting symptoms

4. **Professional Communication**: Clear, actionable documentation that would be useful to development teams

5. **Risk Assessment**: Understanding which issues are critical vs. minor, and their impact on system reliability

You will conduct systematic trial runs of three software programs to verify they produce correct outputs and identify any issues. This exam tests your ability to execute programs, validate results against requirements, and document findings professionally.

### Severity Classification System (Use Exactly These Labels)
- **CRITICAL**: Program crashes or produces completely wrong results

- **MEDIUM**: Edge cases not handled properly or minor calculation errors
- **LOW**: Cosmetic issues or non-essential feature problems

### Deployment Recommendation Options (Use Exactly These Labels)
- **READY**: No critical or high severity issues found
- **NEEDS_FIXES**: Critical or high severity issues must be resolved first
- **REQUIRES_TESTING**: Additional testing needed before decision

#### Program 2: Data Processor (data_processor.py)
- Process the customer_data.csv file
- Validate data transformation and filtering operations
- Check statistical calculations (averages, totals, counts)
- Verify output format matches requirements

#### Program 3: Inventory Management System (inventory_system.py)
- Load inventory_data.json and execute all main functions
