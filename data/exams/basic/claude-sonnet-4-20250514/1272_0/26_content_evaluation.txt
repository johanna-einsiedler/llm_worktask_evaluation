## Explanation of Correct Answers and Derivation

### Critical Bug Fixes (50% of total score)

**BUG001 - Missing Data Persistence**
- **Location**: `update_stock()` method, line 85
- **Issue**: Stock quantity updates are made in memory (`self.products[product_id]['quantity'] = new_qty`) but never saved to the CSV file
- **Evidence**: Clear comment in code states "BUG: Missing call to save_products() - changes not persisted to file"
- **Correct Fix**: Add `self.save_products()` after the quantity update
- **Verification Method**: Update a product's stock, exit program, restart, and verify the change persisted
- **Why Critical**: Without this fix, all stock updates are lost when the program closes

**BUG002 - Missing User Interface Pause**
- **Location**: `run()` method main loop, after each menu operation
- **Issue**: After executing any menu option, the menu immediately redisplays without allowing users to read the results
- **Evidence**: Clear comment states "BUG: Missing pause for user to read results before showing menu again"
- **Correct Fix**: Add `input("\nPress Enter to continue...")` after each menu operation in the main loop
- **Verification Method**: Execute any menu option and confirm system waits for Enter key
- **Why Critical**: Poor user experience makes the system difficult to use effectively

### Feature Enhancement - Low Stock Alert (30% of total score)

**Implementation Requirements**:
- **Alert Threshold**: Products with quantity < 10 units
- **Expected Low Stock Items** (from provided sample data):
  - P002: Organic Cotton T-Shirt (8 units) → Reorder: 58
  - P006: Coffee Mug Set (6 units) → Reorder: 56
  - P009: Backpack (9 units) → Reorder: 59
  - P012: Face Moisturizer (7 units) → Reorder: 57

**Correct Implementation Logic**:
```python
# Loop through products to find low stock items
for product_id, details in self.products.items():
    if details['quantity'] < 10:
        low_stock_products.append({
            'id': product_id,
            'name': details['name'],
            'current_qty': details['quantity'],
            'reorder_qty': details['quantity'] + 50
        })

# Display and save results
for item in low_stock_products:
    print(f"{item['id']:<12} {item['name']:<25} {item['current_qty']:<12} {item['reorder_qty']:<12}")

# Save to file in CSV format
with open('low_stock_alerts.txt', 'w') as file:
    for item in low_stock_products:
        file.write(f"{item['id']},{item['name']},{item['current_qty']},{item['reorder_qty']}\n")
```

**Derivation**: The template function provides clear TODO comments indicating exactly what needs to be implemented. The requirements specify the threshold (< 10), reorder formula (current + 50), and file format.

### Performance Optimization (20% of total score)

**PERF001 - Unnecessary Loop Removal**
- **Location**: `generate_sales_report()` method, lines 140-170
- **Issue**: Redundant `for _ in range(100):` loop makes all calculations 100 times, requiring compensation divisions
- **Evidence**: Clear comments mark "PERFORMANCE BUG: This unnecessary loop makes the report 100x slower - REMOVE THIS LOOP"
- **Correct Fix**: 
  1. Remove the entire `for _ in range(100):` loop wrapper
  2. Remove all `/100` division operations that compensate for the loop
  3. Keep the single iteration through products intact
- **Expected Result**: Report execution time drops from ~10 seconds to <1 second
- **Verification**: Time the report generation before and after the fix
