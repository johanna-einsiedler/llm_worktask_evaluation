## Exam Overview and Purpose

This practical exam assesses a candidate's ability to **actually write, update, and maintain functional computer programs** that solve real-world business problems. Unlike theoretical assessments, this exam requires candidates to produce working code that handles data processing, business logic, and system integration tasks commonly found in entry-level programming positions.

## Strategic Exam Structure

### Core Assessment Philosophy
The exam simulates a **realistic workplace scenario** where a junior programmer receives a business requirement and must deliver a complete, working solution. This approach differentiates candidates who can actually program from those who only understand programming concepts.

### Key Strategic Elements

#### 1. **Multi-Step Problem Solving**
- **Data Input Processing**: Reading and validating data from multiple sources
- **Business Logic Implementation**: Applying rules and calculations
- **Output Generation**: Producing formatted results and reports
- **Error Handling**: Managing edge cases and invalid inputs

#### 2. **Data Relationship Management**
- Working with related datasets (customers, orders, inventory)
- Implementing data joins and lookups
- Maintaining data integrity across operations
- Handling missing or inconsistent data

#### 3. **Decision Points and Branching Logic**
- Conditional processing based on business rules
- Status updates and workflow management
- Alert generation for critical conditions
- Dynamic behavior based on data characteristics

#### 4. **Real-World Constraints**
- Time-based processing (dates, deadlines)
- Quantity and threshold management
- Data validation and sanitization
- Performance considerations for data processing

## Practical Assessment Components

### Primary Task: Inventory Management System
Candidates must build a complete inventory tracking system that:
- Processes incoming shipments and sales transactions
- Updates stock levels automatically
- Generates alerts for low inventory
- Produces management reports
- Handles data validation and error cases

### Secondary Integration: Equipment Control Simulation
Candidates extend their system to:
- Send commands to simulated equipment (printers, scanners)
- Process equipment status responses
- Log equipment interactions
- Handle equipment failure scenarios

## Evaluation Strategy

### Success Indicators
- **Functional Code**: Programs execute without errors
- **Correct Logic**: Business rules implemented accurately
- **Data Integrity**: Proper handling of data relationships
- **Error Management**: Graceful handling of edge cases
- **Code Organization**: Clear structure and maintainability

### Differentiation Factors
- **Problem Decomposition**: How candidates break down complex requirements
- **Data Flow Design**: Understanding of how data moves through the system
- **Integration Thinking**: Ability to connect multiple system components
- **Practical Decision Making**: Choosing appropriate solutions for real constraints

## Optimal Exam Structure

### Phase 1: Core Programming (45 minutes)
- Implement basic inventory tracking functionality
- Process transaction data and update records
- Generate simple reports and alerts

### Phase 2: System Integration (30 minutes)
- Add equipment control capabilities
- Implement cross-system data sharing
- Handle integration error scenarios

### Phase 3: Enhancement and Testing (15 minutes)
- Add requested feature enhancements
- Test edge cases and document findings
- Optimize performance or add validation

## Key Design Principles

### 1. **Authentic Complexity**
Problems mirror real workplace challenges without being overwhelming for entry-level candidates.

### 2. **Measurable Outcomes**
Each component produces specific, verifiable outputs that can be automatically evaluated.

### 3. **Progressive Difficulty**
Tasks build from basic programming to system integration, allowing candidates to demonstrate their skill ceiling.

### 4. **Practical Constraints**
Time limits and resource constraints mirror real development environments.

Candidates submit:

- Documentation of design decisions
- Reflection on challenges encountered

### Automated + Manual Review
- Automated testing of core functionality
- Manual review of code quality and approach
- Assessment of problem-solving methodology
- Evaluation of real-world applicability

## Exam Instructions
You are a junior programmer at TechCorp Industries. Your manager has assigned you to build a basic inventory management system. You have 90 minutes to complete this practical programming exam.

## Your Assignment

### Phase 1: Core Inventory Management (90 minutes)
Build a program that processes inventory transactions and maintains accurate stock levels.

**Requirements:**
1. **Read and process transaction data** from the provided CSV file
2. **Update inventory levels** based on transactions (shipments add stock, sales subtract stock)
3. **Generate low stock alerts** for items with quantity below their reorder threshold
4. **Produce a daily summary report** with total transactions processed
5. **Handle basic validation** - reject transactions that would create negative inventory

**Business Rules:**
- Shipment transactions (type "SHIP") add to inventory
- Sale transactions (type "SALE") subtract from inventory  
- Sales cannot reduce inventory below 0 (reject these transactions)
- Generate alerts when current stock < reorder_threshold
- All item codes must exist in the initial inventory file

## Format Requirements

### String Values
- **item_code**: Use exact codes from CSV files (e.g., "A001", "B002")
- **item_name**: Use exact names from initial_inventory.csv
- **transaction_id**: Use exact IDs from transactions.csv (e.g., "T001", "T007")

### Integer Values
- All quantity and count fields must be whole numbers (no decimals)
- Negative quantities are not allowed in final inventory
- All summary counts must equal the sum of their components

### Array Ordering
- **final_inventory**: Order by item_code alphabetically
- **low_stock_alerts**: Order by item_code alphabetically  
- **rejected_transactions**: Order by transaction_id

### Validation Rules
- All item_codes in transactions must exist in initial_inventory.csv or be rejected
- Sales cannot reduce inventory below 0 (reject transaction if insufficient stock)
- Low stock alerts only for items where current_quantity < reorder_threshold

### Source Code Format
- Include complete, executable program code as a single string
- Use proper escape characters for quotes and newlines within the JSON string
- Code should be readable and well-commented

## Important Notes
- Use the exact item codes and transaction types provided in the data files
- Your program must handle all transactions in the provided CSV file
- All numerical values in your JSON output must be exact integers
- Test your program thoroughly before submitting

## Evaluation Criteria
Your solution will be evaluated on:
- **Functionality**: Does your program correctly process all transactions?
- **Accuracy**: Are inventory levels and calculations correct?
- **Error Handling**: Does your program properly reject invalid transactions?
- **Code Quality**: Is your code well-structured and maintainable?

## Helpful Tips
- Use simple data structures like dictionaries/maps to store inventory data
- Process transactions one at a time in chronological order
- Test with a few transactions before processing the entire file
- Focus on getting the core inventory calculations correct - this is the most important part
- Remember that transactions T007, T012, and T013 should be rejected for different reasons
- Start by reading the CSV files and understanding the data structure
- Build incrementally - get basic transaction processing working first, then add validation

## Sample Program Structure
Here's a suggested approach to get you started:

```python
# 2. Read transactions from CSV
# 3. For each transaction:
#    - Check if item exists
#    - Check if transaction is valid (no negative inventory)
#    - Update inventory or reject transaction
# 4. Generate reports (final inventory, alerts, summary)
# 5. Format output as JSON
```
