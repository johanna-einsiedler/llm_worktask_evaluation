## Detailed Answer Derivation

### Final Inventory Calculations

Starting from initial_inventory.csv, process each valid transaction in order:

**A001 (Widget Alpha)**: 100 + 50 - 80 = 70
- T001: SHIP +50 → 150
- T005: SALE -80 → 70

**A002 (Widget Beta)**: 75 + 30 - 50 = 55
- T003: SHIP +30 → 105
- T011: SALE -50 → 55
- T007: SALE -120 → REJECTED (would result in -15, insufficient inventory)

**B001 (Gadget Pro)**: 200 - 25 + 75 = 250
- T002: SALE -25 → 175
- T008: SHIP +75 → 250
- T012: SALE -300 → REJECTED (would result in -50, insufficient inventory)

**B002 (Gadget Lite)**: 40 - 30 - 5 = 5
- T006: SALE -30 → 10
- T010: SALE -5 → 5

**C001 (Tool Master)**: 150 - 60 - 45 - 20 = 25
- T004: SALE -60 → 90
- T009: SALE -45 → 45
- T014: SALE -20 → 25

### Rejected Transactions Analysis

1. **T007**: A002 SALE 120 - Current stock after T003 is 105, insufficient for sale of 120
2. **T012**: B001 SALE 300 - Current stock after T008 is 250, insufficient for sale of 300
3. **T013**: X999 SALE 10 - Item code X999 doesn't exist in initial inventory

## Passing Criteria and Scoring Rubric

### Minimum Requirements for Passing (80% threshold)

**Total Points: 100**
**Passing Score: 80 points**

### Detailed Scoring Breakdown

**1. Final Inventory Calculations (35 points)**
- All 5 items calculated correctly: 35 points
- 4 items correct: 28 points
- 3 items correct: 21 points
- 2 items correct: 14 points
- 1 item correct: 7 points
- 0 items correct: 0 points

**2. Transaction Processing Logic (25 points)**
- All 3 rejections identified correctly with proper reasons: 25 points
- 2 rejections correct: 17 points
- 1 rejection correct: 8 points
- No rejections identified correctly: 0 points

**3. Low Stock Alerts (10 points)**
- Correct identification of B002 and C001 only: 10 points
- One correct alert (either B002 or C001): 5 points
- Incorrect alerts or missing alerts: 0 points

**4. Daily Summary Accuracy (10 points)**
- All summary counts correct: 10 points
- 3 out of 4 counts correct: 7 points
- 2 out of 4 counts correct: 5 points
- 1 out of 4 counts correct: 2 points
- No counts correct: 0 points

**5. Equipment Integration (15 points)**
- All equipment commands correctly mapped and sequenced: 10 points
- Equipment summary calculations correct: 5 points
- Partial equipment functionality: 7 points
- No equipment integration: 0 points

**6. Code Quality and Execution (5 points)**
- Code executes without errors and produces correct output: 5 points
- Code executes with minor issues: 3 points
- Code partially functional: 1 point
- Code doesn't execute: 0 points

### Grade Boundaries

- **90-100 points**: Excellent (A)
- **80-89 points**: Good (B) - **PASSING**
- **70-79 points**: Satisfactory (C) - **NOT PASSING**
- **60-69 points**: Needs Improvement (D) - **NOT PASSING**
- **Below 60 points**: Unsatisfactory (F) - **NOT PASSING**

### Critical Success Factors

To pass this exam, candidates must demonstrate:

1. **Core Programming Competency**: Ability to read data, process it according to business rules, and produce accurate results
2. **Data Validation Skills**: Proper handling of invalid transactions and edge cases
3. **System Integration Understanding**: Basic ability to connect different system components
4. **Problem-Solving Approach**: Logical breakdown of complex requirements into manageable components

### Common Acceptable Variations

- Different programming languages (Python, Java, C#, JavaScript, etc.)
- Alternative data structure approaches (arrays vs. dictionaries)
- Minor formatting differences in source code
- Reasonable alternative testing notes reflecting actual findings
- Different but equivalent error handling approaches

### Automatic Failure Conditions

- Non-executable code that produces no output
- Missing required JSON fields
- Incorrect data types (e.g., strings instead of integers for quantities)
- Major calculation errors affecting more than 60% of inventory items
- Complete absence of transaction validation logic

### Evaluation Notes for Graders

1. **Focus on Functionality**: The primary goal is working code that solves the business problem
2. **Accept Multiple Approaches**: Various programming styles and structures are acceptable if they produce correct results
3. **Partial Credit**: Award partial credit for partially working solutions that demonstrate understanding
4. **Real-World Relevance**: Consider whether the solution would be maintainable and useful in a professional environment

This evaluation framework ensures that candidates who pass can actually perform the essential tasks of computer programming in an entry-level professional role, while providing clear, objective criteria for assessment.
