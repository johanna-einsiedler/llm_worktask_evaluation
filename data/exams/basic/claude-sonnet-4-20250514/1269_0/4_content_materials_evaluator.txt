## Material Creation Strategy

### Buggy Program Design
The `buggy_program.py` file contains a functional inventory management system with **intentional compilation errors** strategically placed to test different competency levels:

**Compilation Errors Included:**
1. **Line 4**: Missing import statement - `import json` is included but never used, while `datetime` import is present but the program uses `datetime.now()` correctly
2. **Line 47**: Logic error - The program attempts to access `self.inventory[item_id]['quantity']` but should handle the case where quantity becomes 0
3. **Line 89**: Indentation error in the `generate_report` method
4. **Line 105**: Variable scope issue - `manager` variable used before proper initialization check

**Expected Fixes:**
- Remove unused `import json` (optional improvement)
- Fix indentation in `generate_report` method
- Add proper error handling for edge cases
- Ensure proper variable initialization

### Sample Data Structure
The `sample_data.txt` contains exactly 4 inventory items with predictable data:
- **ITEM001**: Laptop Computer, 10 units, $899.99 each
- **ITEM002**: Desktop Monitor, 25 units, $249.50 each  
- **ITEM003**: Keyboard, 50 units, $45.00 each
- **ITEM004**: USB Cable, 100 units, $12.99 each

**Total Initial Inventory Value**: $30,547.40
- ITEM001: $8,999.90
- ITEM002: $6,237.50
- ITEM003: $2,250.00
- ITEM004: $1,299.00

### Program Execution Flow
When corrected and run, the program should:
1. Load 4 items from sample_data.txt
2. Add ITEM005 (Wireless Mouse, 15 units, $29.99)
3. Add 5 more ITEM001 (increasing laptop quantity to 15)
4. Remove 3 ITEM002 (reducing monitor quantity to 22)
5. Look up ITEM003 information
6. Generate final report

**Expected Final Inventory Values:**
- ITEM001: 15 units, $13,499.85 total value
- ITEM002: 22 units, $5,489.00 total value
- ITEM003: 50 units, $2,250.00 total value
- ITEM004: 100 units, $1,299.00 total value
- ITEM005: 15 units, $449.85 total value
- **Final Total Value**: $22,987.70

### Key Assessment Points

**Documentation Quality Indicators:**
- Candidates should identify 6 functions requiring documentation
- Each function has clear input/output parameters for objective evaluation
- Installation instructions should include Python requirements and file placement

**Comment Quality Differentiation:**
- **Strong candidates** will explain business logic (why inventory tracking matters)
- **Weak candidates** will only restate obvious code operations
- **Critical comments needed**: Error handling logic, calculation explanations, file I/O operations

**Common Pitfalls:**
1. **Missing the indentation error** - most obvious compilation issue
2. **Over-commenting obvious code** - shows lack of understanding of comment purpose
3. **Incomplete testing documentation** - failing to verify program works with sample data
4. **Generic function descriptions** - not explaining specific business purpose

**Tricky Elements:**
- The program includes both used and unused imports (testing attention to detail)
- Error handling is partially implemented (candidates must decide what to improve)
- Transaction logging feature exists but isn't fully utilized (opportunity for improvement documentation)

**Objective Verification Points:**
- Program must compile and run without errors
- Final inventory report must show correct calculated values
- JSON structure must match exactly (automated checking possible)
- All 4 sample data items must be loaded successfully

This design ensures candidates demonstrate actual programming competency rather than just theoretical knowledge, with clear right/wrong answers for objective evaluation.
